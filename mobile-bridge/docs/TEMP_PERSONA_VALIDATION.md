# 临时人设插件验证记录

验证日期：2026-10-28。插件：`temp-persona` 0.1.0。使用方式和数据范围见 [TEMP_PERSONA.md](TEMP_PERSONA.md)。

## 验证结果

- 42 项针对性测试通过：原文先归档、归档失败不建立索引或推进游标、Unicode 与换行保留、首次启用基线、分批处理、来源校验、修订与回退、并发编辑和冻结、停用时的在途结果、模型错误、调度及导出。
- 反思客户端通过本地 HTTP 模拟服务验证 OpenAI 兼容请求、Bearer 认证、JSON 响应、无变化响应、来源编号检查及失败处理。未使用真实外部模型。
- Python 静态检查通过；页面 JavaScript 语法检查通过。

## 未修改宿主上的实际闭环

最终从最新宿主提交 `12668846a17128056067d47c44774a5c24a70b99` 的 `git archive` 创建独立运行目录，通过 Nexus 自身插件管理 API 导入发布 ZIP 并加载，没有修改宿主代码。此前也在 `908ceb5` 上完成过初次闭环验证。

1. 在安装前进行一次主对话，安装后通过宿主的新历史编辑接口删除这些消息，再发送新交流。验证旧内容不进入插件原文归档或反思输入，历史缩短、位置复用后新交流仍被完整归档。
2. 安装后发送带换行和表情的中文反馈，配置本地模拟反思服务，手动触发反思。有效修订自动生成版本 2，所有者设定保持不变，原始模型响应及引用依据可读取。
3. 再次进行主对话，检查真正发给模型的系统材料包含人设版本 2。该检查证明材料参与请求，不代表真实模型必然遵循或行为已经改善。
4. 将每日时间暂设为下一个本地分钟，等待真实调度线程触发第二次反思；模拟服务返回无需修改，待处理游标正常推进。
5. 停用、加载、重启宿主，确认版本持久保留，重启没有重放已经过期的定时任务。
6. 导出后核对 SQLite 快照、可读人设、修订、反思记录及所有原文文件的 SHA-256；原始中文换行和表情仍在，凭据文件及测试密钥没有进入导出。

本次闭环使用 3 次主对话模型请求和 2 次反思请求，均由本地模拟服务响应。

## 验证边界

- 仅向主对话提供材料、跨日时间计算、忙碌时等待、冻结时手动反思只保留候选、无新内容不调用模型，以及反思期间编辑／回退／冻结后恢复均有针对性测试。
- 外部真实服务的兼容性、反思质量和长期行为效果未验证；Windows 实机、长期运行、夏令时切换和系统时钟调整未进行实机验收。
- 测试验证插件接口与自身数据流，未运行宿主全量回归。发布仅包含插件 ZIP 和文档；开发源码、测试、模型模拟器、运行资料和工具缓存留在暂存子目录。
- 冻结或停用阻止在途结果自动应用，但不会撤回已经发送给服务的请求；其返回内容仍可作为候选留档。
