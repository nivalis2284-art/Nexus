# Nexus

Nexus 是一个正在迭代的个人 Agent 项目。**当前版本**提供灵的持续交流入口与独立持久任务：用户可以继续交流，由灵发起、了解和干预工作，并接收重要事件。原有 Coding Agent 的网页会话、模型接入、工具与运行控制继续保留。

当前暂停新增功能，维护重点为减少重复实现、厘清运行与业务边界、精简历史验证产物。Demo 的使用方式和已有产品目标保持不变；本轮变更、验证结果和保留的技术债务见 [`docs/archive/2026-10-21-phase1-baseline/PROGRESS.md`](docs/archive/2026-10-21-phase1-baseline/PROGRESS.md)。

当前项目尚未实现长期记忆或人格等愿景能力；这只是版本现状，**不代表未来的功能限制**。长期方向见 [`docs/愿景/`](docs/愿景/)，当前要做什么以已确认的需求为准。

## 快速开始

当前主要面向 Windows，使用 Python 3.12。

1. 双击 `start.bat`。首次启动会按脚本配置创建虚拟环境、安装依赖。
2. 在浏览器打开 `http://127.0.0.1:8766`（通常由启动脚本打开）。
3. 在设置中填写模型提供商的 Base URL、模型名称、协议及 API Key，然后开始对话。

启动脚本会检查 Python 3.12 和项目依赖。若现有 `.venv` 已失效，会先保留为同目录下的 `.venv.invalid-<时间>` 备份，再创建环境；不会删除原环境或覆盖会话数据。环境准备失败时，终端会显示具体原因。

如果默认数据目录不可写，可显式选择有写入权限的目录，例如 ` .\.venv\Scripts\python.exe -u -m nexus --home .nexus-data --workspace . --port 0`，以终端输出地址为准。该选项使用独立数据目录，不自动迁移原目录的历史；已有 Nexus 实例应先退出再使用同一目录重新启动。

仓库不预置可直接使用的模型服务与密钥。依赖和 Python 版本范围以 [`pyproject.toml`](pyproject.toml) 为准。

## 当前功能概览

| 业务能力 | 当前实现 |
|---|---|
| 模型交互 | Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 三类协议；支持流式输出 |
| 模型管理 | 多提供商配置、切换模型、思考强度设置 |
| Agent 执行 | 多轮工具调用及结果回灌、停止操作、模型请求重试 |
| 基础工具 | 文件操作、命令、后台任务、补丁、待办与向用户提问 |
| 扩展能力 | 子代理、Skill、MCP；网络工具按配置启用 |
| 上下文 | 会话历史、上下文裁剪与摘要压缩 |
| 持久任务 | 任务库、并存的待执行/挂起任务、任务进度与证据、暂停/继续、跨重启恢复 |
| 灵的持续交互 | 固定交流入口、服务端持久输入队列；灵可委派、查询和干预独立工作，执行过程留在任务内 |
| 重要事件反馈 | 页内主动提示和决策作答，完成/受阻/等待用户等事件持久保存，离线回来补看 |
| 自主活动（开发中，待真实模型验收） | 唯一灵主 Agent 有界审议、持久关注事项、自定回顾、独立本地资料监听、授权内独立工作与正式主动消息 |
| 执行安排 | 默认手动；可选一次性到时自动恢复或等待确认，错过后等待用户 |
| 任务止损 | 记录尝试和已排除路线；同前提无新依据的重复失败会停止该路线 |
| 网页交互 | 聊天界面、思考与工具过程展示、授权确认 |
| 文件附件 | 普通会话与持久任务上传、保存和下载原件；Agent 按段读取文本、PDF、DOCX、XLSX/XLSM、PPTX |

这些是现状说明，不是未来开发必须保留的架构和功能清单。具体行为请以代码与实际运行结果为准。

## 模型配置与数据

三个协议标识：

- `anthropic_messages`：通常使用 `/v1/messages`
- `openai_chat_completions`：通常使用 `/v1/chat/completions`
- `openai_responses`：通常使用 `/v1/responses`

思考强度设为“提供商默认”时不主动传入强度字段；也提供 `low`、`medium`、`high`、`xhigh`、`max` 档位。实际支持情况取决于模型、服务端及协议实现，并非所有服务都必然接受全部档位。

数据目录默认为 `%LOCALAPPDATA%\Nexus`，可用 `NEXUS_HOME` 调整。常见内容：

```text
config.json          提供商及运行配置（不含 API Key）
credentials.json     API Key 等凭据
sessions/*.jsonl     会话记录
tasks.sqlite3        持久任务、执行证据、交互、一次性安排、通知与灵的输入队列/归属
attachments/         按会话/任务归属保存的原文件、元数据与提取文本
autonomy-observer/   可替换监听 MCP 的规则、基线与事件日志；重要自主记录仍在 tasks.sqlite3
skills/*.md          可选 Skill 文档
```

凭据请勿提交到 Git、公开上传或复制进日志；实际访问控制还取决于操作系统与目录权限。删除或覆盖数据目录会造成记录及配置丢失，操作前应自行备份。

## 与灵交流和管理工作

默认进入「灵」的持续交流入口，旧普通会话和持久任务仍可从侧栏进入。耗时工作可由灵通过 `work_start` 转为独立持久任务；灵取得工作引用后继续交流，可以通过工作工具查询状态、分页读取证据、补充要求，以及暂停、恢复或取消明确的工作。任务模型执行目前仍是单 Worker 串行安排；多个任务能够保存、等待或排队，不代表多个任务模型同时推进。已启动的后台命令在等待用户时仍可继续。

灵的输入先保存到服务端队列，网页断开不终止已接收的主体交互或独立工作。运行中发送新问题会排队，不隐含停止；「停止当前交互」只停止当前灵回复，独立工作需明确暂停/取消。普通会话继续保留原有的流式与停止行为。灵的主体记录不列入普通会话的删除列表，旧普通会话的删除行为不变。

重要事件会主动展开页内通知，保留关联任务、结果或阻碍；需要审批/回答时可在通知里处理，也可进入原任务页。提示已读与工具授权分开：标为已读不会批准操作；过期请求会重新核对当前状态。切换会话不会清空草稿或停止独立工作，离线回来可以补看通知。

独立工作按安全边界保存消息与操作结果，新的补充要求在下一模型请求边界送入，查询可见待送入数量。通过灵补充要求不会自动恢复已挂起的工作；任务页原有的「发送到挂起任务即继续」行为保留。新的灵委派工作在正常轮次结束但目标尚未完成时有限继续，无进展、预算/步数限制、明确阻碍、权限等待或用户暂停会清楚停止；旧手动任务保留原来的轮末挂起行为。恢复会利用保存状态并核查未知结果，不恢复旧进程或自动重放可能产生副作用的输入。

重启后，未开始的灵输入等待用户明确继续；上次正在处理的输入标为中断，需检查已生效操作后发新消息继续，不盲目重放。独立任务沿用已有的中断核查和手动恢复边界。完整长期记忆、人格演化和站外系统推送仍不在本阶段。

## 启用与管理自主活动

自主活动默认关闭。先配置可用模型，再打开顶部「自主」，在「设置与长期授权」中填写获准读取的资料目录、成果保存目录和有限的 Token 总额度，保存后明确启用。建议首次使用选择专门的测试资料目录。模型使用当前 Nexus 配置；保底回顾默认 6 小时，主动联系等待默认 24 小时，参数可调整。到时只提供审议机会，不保证创建工作或发送消息。

灵的同一个主 Agent 负责形成关注事项、安排未来回顾、管理获准监听，以及决定行动、等待或沉默。实际调查交给现有持久工作执行，真实结果回到下一次判断。自主消息保存在服务端，出现在灵的交流历史与「主动消息」内，并有页内提示和未读数；点开来源可以读取实际记录。关闭网页不会停止仍在运行的 Nexus 服务，退出服务会停止活动。

「暂停」会停止继续审议、关闭监听并暂停关联自主工作；「恢复」只继续能够确认仍由本次暂停持有的工作，未知副作用或已有决策请求仍需核查。「终止」取消自主计划和关联工作，历史与额度账本保留；再次启用需明确操作。单个关注事项可撤回，其计划、监听和旧工作不会因此被自动重新创建。普通聊天和用户自行建立的任务继续使用原有控制。

首版监听器是独立 stdio MCP，支持 UTF-8 `.txt`、`.md`、`.markdown` 文件及其目录。它检测扫描时刻的内容变化，无法保证捕获两次扫描之间短暂出现又消失的版本；基线和观察间隙会与客观变化区分。单文件读取上限 2 MiB、每项监听最多 512 个文件、单事件证据保留前 64 KiB，超限或覆盖不足有明确记录。其他文件能力仍可通过原有工具和附件使用，不代表监听器已支持其格式。

授权内读取和写入成果目录可以直接进行；其他具体调用仍走现有持久任务审批。高级设置中的 MCP 工具名单只决定暴露哪些工具，不代表预先批准外部写入。每次自主模型请求（含子代理、摘要与重试）先预留额度，成功后按服务商 usage 结算；中断或 usage 不明时保留预留额。额度为累计总量，修改设置、暂停或重启不会清零。UTF-8 字节预留是保守估算，并非服务商精确账单或绝对计费上限。

当前交付证据与尚未验证的真实模型行为见 [docs/archive/2026-10-21-phase1-baseline/PROGRESS.md](docs/archive/2026-10-21-phase1-baseline/PROGRESS.md)。工程联通测试不等于自主性产品验收通过。

## 上传和使用附件

输入框左下角“＋ 附件”支持选择文件，也可以拖拽或粘贴。每次最多 8 个附件，普通文件单个上限 25 MiB，图片单张上限 5 MiB；允许只发送附件。发送前可移除，上传或消息提交失败时保留当前草稿以便重试。草稿是当前页面状态，尚未发送的文件不保证跨页面刷新恢复。

普通会话和持久任务都会保存已发送附件，历史消息中可点击文件名下载原件。刷新或重启后仍可使用，删除会话或任务时一并清理所属附件；归档或挂起不删除。持久任务保留原有手动开始语义：向待执行任务发送附件不会自行启动任务。

Agent 从消息中取得文件标识和原件路径，通过 `read_attachment` 按行分页读取提取文本。原文件不会被自动执行，也不会因为上传就把整个大文档塞进模型上下文。

| 文件类型 | 当前直接读取范围 |
|---|---|
| 文本、代码、Markdown、CSV、JSON 等 | UTF-8、带 BOM 的 UTF-16 和 GB18030 文本 |
| PDF | 文本层，保留页码；不提供扫描件 OCR 或视觉版面复原 |
| DOCX | 正文段落和表格 |
| XLSX、XLSM | 工作表、单元格地址、内容和公式源码；不执行宏或重新计算公式 |
| PPTX | 幻灯片文字、表格、分组内文字和备注 |
| 图片 | PNG、JPEG、WebP、GIF；普通会话与任务均需对应模型声明并实际支持图片能力 |
| 其他文件，包括旧版 DOC/XLS/PPT、压缩包等 | 保存原件，按现有工具能力处理，不保证直接解析 |

提取文本最多保留 200 万字符，超过时明确标记，原件仍完整保存。损坏、加密或没有可提取文字的文件会显示读取限制。正文读取不等同于完整视觉理解，文档中的插图、复杂图表和排版可能需要原文件及其他工具核对。

## 工具与权限

设置支持 `ask`（关键操作请求确认）与 `yolo`（允许更多自动执行）两种模式，也支持通过 `config.json` 配置具体工具规则。规则使用后匹配覆盖前匹配的方式：

```json
"permissions": [
  {"tool": "bash", "pattern": "*", "action": "ask"},
  {"tool": "bash", "pattern": "git *", "action": "allow"},
  {"tool": "bash", "pattern": "rm *", "action": "deny"}
]
```

这是应用层授权控制，**不能等同于操作系统沙箱或完整隔离**。尤其在 `yolo` 模式下，请只在可信环境中授予适当的文件与命令权限。停止命令不保证回滚已经完成的外部操作。

耗时操作可使用后台任务工具；如需查看其细节或具体参数，请以工具定义和当前实现为准。

后台任务按会话保存，在同一会话的后续轮次可继续查看输出或停止；其他会话有独立列表。服务退出时清理后台任务，重启后不恢复。停止当前 Agent 运行与停止后台任务是不同操作，后者使用 `job_kill`。

持久任务在侧栏单独管理，可通过手动开始、自然语言短指令或一次性安排恢复。任务挂起会停止该任务自己的后台命令并保留已知输出；任务等待审批/提问时，已运行的后台命令允许完成。普通会话的原有停止语义保持不变。

## 可选能力

**网络工具**默认不注册；需要时在配置中提供允许访问的站点或搜索服务：

```json
"webfetch_hosts": ["docs.python.org", "github.com"],
"search_endpoint": "https://your-search.example/api"
```

**MCP** 可通过 stdio 服务器接入外部工具，例如：

```json
"mcp": {
  "servers": [
    {"name": "fs", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "."]}
  ]
}
```

上述 MCP 配置是示例；运行第三方服务器前需确认其来源、依赖和可访问范围。工具可用性取决于本地环境。

**Skill** 可从工作区 `.nexus/skills/<名称>/SKILL.md` 或用户目录 `~/.nexus/skills/<名称>/SKILL.md` 发现；实际读取方式由现有 Skill 机制决定。

## 项目结构

```text
nexus/
  core/       Agent 循环、上下文、配置与权限
  model/      模型传输与协议解析
  tools/      内置工具及注册
  session/    JSONL 会话存储
  web/        HTTP 服务、HTML/CSS/JavaScript 前端
  mcp.py      MCP 客户端
  skills.py   Skill 发现
tests/        自动化测试
docs/         愿景与历史参考等文档
AGENTS.md    开发协作说明
```

当前使用 Python 标准库提供 HTTP 服务，前端为无需构建的单页应用；这些是实现现状，不是不可改变的技术规定。

## 代码组织偏好（非强制）

为了便于维护，目前倾向于小型共同基础、按职责组织模块、通过清楚的接口协作，并将易变的外部技术适当隔离。早期可优先考虑结构清晰的模块化单体。

**这些只是经验性偏好，不是架构约束或验收标准。** 不要求强制分层、依赖注入、插件化或彻底解耦；业务之间可以存在合理的深度依赖。若当前需求、实际代码或维护成本表明其他组织方式更合适，可以自主调整，不必为了符合上述偏好而增加额外抽象。

## 开发与测试

安装开发依赖后，在仓库根目录运行：

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe -m pytest tests -q
```

测试覆盖范围、通过数量及真实模型验证情况会随版本变化；请以当前测试运行结果为准。自动化测试通过不等于所有功能已经完成实际操作验收。
