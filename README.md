# Nexus

Nexus 是由所有者掌握的个人 Agent 底座。当前版本收敛到一个主交流入口“灵”和即时后台工作：在交流中交代、补充和干预工作，工作独立推进，结果或需要决定的事项回到主交流。

[《01-概念与原则》](docs/愿景/01-概念与原则.md)是最高原则。当前职责整理见[内核边界收束与 Web 解耦计划](docs/当前阶段/Nexus内核边界收束与Web解耦计划.md)。前轮[上下文、子代理协作与提示词优化计划](docs/当前阶段/Nexus上下文与子代理协作优化计划.md)保留实现与真实模型验收限制；更早记录见[业务收敛与优化计划](docs/当前阶段/Nexus业务收敛与优化计划.md)。历史资料保留在 `docs/参考/`，不作为当前功能说明。

## 启动

主要面向 Windows，使用 Python 3.12。

1. 双击 `start.bat`；脚本检查虚拟环境并准备项目依赖。
2. 打开终端输出的本机地址，通常为 `http://127.0.0.1:8766`。
3. 在设置中填写模型提供商、协议、Base URL 与 API Key，选择模型与思考强度。
4. 进入“灵”直接交流。耗时工作由灵派发，点击关联工作查看只读详情；补充要求仍从主交流发送，可选择其关联工作。

通过 `start.bat` 默认使用仓库内 `.nexus-data`。可以用 `NEXUS_HOME` 或 `--home` 指定其他数据目录；不会自动迁移另一个目录。直接运行 `python -m nexus` 默认使用 `%LOCALAPPDATA%\Nexus`。同一数据目录只运行一个实例。

```powershell
.venv\Scripts\python.exe -m nexus --home .nexus-data --no-browser
```

首次启动与依赖说明以 [pyproject.toml](pyproject.toml) 和启动脚本为准。仓库不包含可用的模型密钥。

未选择项目时，工作目录使用根目录下自动创建的 `Work/`。在主交流页点击项目名称，可选择历史项目，或创建项目记录；「添加」会打开本机系统文件夹选择窗口，选择已有目录或在系统窗口内新建目录。名称默认取文件夹名称，可自行修改。重命名和移除只改项目记录，保留磁盘文件及已有任务；移除当前项目后切回 `Work/`。当前选择和项目历史保存在数据目录中，重启后保留；显式传入 `--workspace` 可覆盖当前目录。切换需等待主交流空闲，已有后台工作继续使用各自原来的目录。系统目录选择依赖 Python 自带的 Tk，在运行 Nexus 服务的电脑上打开。

模型设置中的“最大输出”是单次请求允许生成的 token 数；部分推理模型的思考内容也消耗这一额度。数值须符合模型及接入服务的限制。Responses 协议在未设置时默认请求 8192；若服务明确报告达到输出上限或触发内容过滤，任务会显示原因并保留为挂起。

根目录 `Cache/` 保存 Nexus 产生的临时工作文件，截图位于 `Cache/screenshots/`。Agent 运行的命令使用该目录作为 TEMP、TMP 和 TMPDIR；程序自行指定的路径不受此设置约束。缓存可手动清理，不要将正式交付物存放其中。为保证文件原子替换，配置及会话写入时的临时文件仍放在目标文件旁。

支持图片的模型可调用 `screenshot` 查看 Windows 桌面或 URL 对应网页。网页截图使用单独的临时 Edge 会话，不包含日常浏览器的登录状态，也不会连接用户正在操作的浏览器；截图保存在缓存，图像内容会进入模型上下文与会话历史。

## 内核与 Web 的职责

`nexus/application.py::Application` 持有主交流、工作调度、MCP、插件、实时事件及后台进程资源，提供现有交流输入、设置和生命周期入口；`runtime/conversation.py` 恢复模型历史，`runtime/settings.py` 保存设置，`runtime/work.py` 提供工作操作。这些实现不导入 Web 层。

`nexus/web/` 负责 HTTP／SSE、页面展示转换和静态资源，通过应用及现有业务模块处理操作。更换 Web UI 可沿用当前接口和事件，网页文件仍随同一个 Python 包分发。当前启动方式和功能保持，尚未新增 CLI 或独立前端部署。

应用可在没有 HTTP Handler 的情况下运行：创建 `Application().start(home=数据目录)` 后，通过 `submit_input` 提交包含 `text` 和 `request_id` 的输入，通过 `inbox()` 和 `state` 读取现有交流、工作及事件资源，结束时调用 `close()`。插件的页面和 HTTP 回调仍依赖宿主实际绑定的服务地址，由宿主调用 `attach_http` 后启动相应插件资源。

## 日常交流与工作

前端设计与后续页面开发遵循 [设计规范](docs/设计/DESIGN.md) 和 [页面接入模板](docs/设计/页面模板.md)。[可运行组件样张](docs/设计/页面模板.html) 使用独立资源副本，可在浏览器中查看；经确认的设计按[迁移约定](docs/设计/预览与迁移.md)进入正式前端。正式页面的几何、间距、字号与动效参数统一由 `nexus/web/css/tokens.css` 提供。

- 主交流和工作均由服务端运行，关掉网页不会停止已接收的工作；退出服务会中断执行。重启后须明确继续，不恢复旧进程，不自动重放结果未知的操作。
- 主交流运行中发来的消息先保存，在下一模型请求边界送入。新话题不会取消后台工作。
- 后台最多同时执行三个工作，更多工作排队；同一 Git 项目（非 Git 则为工作目录）的修改串行。只读研究可以并行，转为可能产生副作用的工具前取得该项目写入资格。不自动创建工作树或复制项目。
- “停止当前交流”停止主交流及其直接委派的子代理；已经派发的独立顶层工作继续。后台工作分别暂停或取消，也可明确“暂停全部工作”。父工作暂停／取消会传递给所属子代理。暂停保留现场；只补充信息不会自动恢复。
- 审批和问题有明确归属；在主交流中作答，其他消息不算批准。等待决定时仍可继续其他交流。
- 工作完成、受阻或需要决定时，由灵结合交流解释情况；完整结果、工具记录、附件和未确认操作保存在工作详情。已完成结果需要修改时，沿用同一个工作开始新一轮，保留旧结果。
- 灵可以为工作选择已配置的模型和思考强度，并在后续请求边界调整；所有者的明确指定优先。主交流模型由所有者选择。历史与工具结果独立保存，不因更换模型而重放工具。
- 所有者基本原则与交流偏好可在“上下文管理”中逐条添加、编辑与删除，也可明确让灵修改；后续请求生效。后台工作只读取，不自行改写。

## 上下文管理与消息操作

侧栏“上下文管理”按来源展示所有者指令、主交流／后台工作／子代理三个角色的完整规则，以及环境、项目指令、技能、工作观察、权限和工具等只读信息。角色修改用于相应代理后续的模型请求。页面展示当前组装来源，不把它冒充为此前某次请求的原文。

历史上下文分为已压缩摘要和未压缩消息。摘要显示全文，点击编辑后修改；近期消息可选择删除。所有修改持久化到实际数据，刷新页面仍保留。运行中的主交流须先停止或等待完成，再修改摘要或历史消息；后台工作继续独立运行。

主交流消息下方提供复制、删除；自己的近期消息还可以编辑后重新发送。编辑统一通过弹窗确认，取消不生效，保存失败保留输入。重新发送从该条消息继续，替换其后交流记录，保留本条附件和工作归属；已经执行的工具、文件修改和后台工作不回滚。已压缩的历史通过摘要编辑管理，聊天仍保留原文供查阅与复制。

最近一次历史修改可在会话继续前撤销；重新发送的这一轮回答完成后，仍可在下一条输入前撤销。撤销现场只保留在当前服务进程中，重启后不再提供。页面提供“灵玉／星枢”两套昼夜主题，默认使用“星枢 · 黑夜”，保留浏览器中已保存的主题选择。卡片使用不透明表面，中枢作为背景常驻，切换页面或开始交流后继续保留。界面包含轻量过渡和弹窗／消息进入动效，并遵循系统“减少动态效果”偏好。

主交流以消息身份衔接发送中的气泡、实时回复和正式记录；流式正文经过短缓冲渐显，并逐步呈现 Markdown 排版。停在最新位置时平滑跟随，主动上翻后保留阅读位置，可点击“最新”恢复跟随。灵玉与星枢共用正文结构，引用块保留引用线。

侧栏的眼睛按钮可以隐藏界面，只保留导航与动态背景；长按并拖动中枢可交互，再点按钮或按 Esc 恢复。隐藏期间会话继续接收回复，保留草稿与阅读位置；点击页面导航会恢复界面，刷新后也恢复正常显示。

## 上下文与子代理协作

长历史先缩短模型请求中的过长工具结果，再按容量生成摘要检查点。摘要前会分段覆盖长消息全文；成功后保存覆盖范围，跨轮和重新加载继续使用，原始交流、工具记录与附件仍保留。容量计算包括系统提示、工具定义、消息、图片和当前强度对应的输出预留；同一路由且口径一致的实测输入用量用于校准。无法容纳或摘要失败时明确报告容量问题。

主交流和顶层后台工作可以用 `subagent` 启动独立子代理，立即取得标识并继续其他工作。默认传入独立的任务说明；`context_mode="fork"` 复制当时有效的历史与附件，之后父子分别保存。`subagent_list/read/message/control/model` 提供查询、定向补充、暂停／恢复／取消和模型调整；`subagent_wait` 让父工作释放执行位等待，结果或待决定事项返回父工作。子代理共用三个后台执行位，同项目写入继续串行。首版只允许一层委派，子代理以 `task_finish` 完成自己的任务。

工作详情显示父子归属和子代理入口；审批仍分别属于具体子代理和操作。已完成子代理可以在同一标识下接收新的明确补充，已取消子代理须先明确恢复。手动暂停的父工作不会因子代理结果到达而自动恢复。

项目指令只从工作目录及已触及的子目录读取，不继承工作目录上级的指令文件。指令标明文件来源及目录范围，每次请求更新；首次通过文件工具触及子目录时读取相应规则，新规则在首次写入前交给模型。所有者当前明确要求优先于一般偏好及旧摘要。默认 `ask` 仍按具体操作审批，`yolo` 不解除文件工具的工作目录边界；当前版本没有附加只读目录授权。

模型返回的可重放原生推理信息随历史保存，只在相同协议、模型及提供商路由下重放；不同模型仍使用通用文字和工具历史。三种协议的自动化闭环已覆盖，当前真实模型复杂委派尚未通过验收，详见优化计划中的实施记录。

## 保留能力与本轮退出范围

保留 Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 三类模型协议、流式交流、文件和命令、后台进程、附件原件及分页读取、Skill、MCP 与普通插件接入，以及权限规则、上下文裁剪和摘要压缩。

Windows 默认使用 `powershell` 和 `powershell_background` 命令工具，支持 PowerShell 内建命令、脚本和管道；每次从工作目录启动新的进程。已有的 `bash` 和 `bash_background` 保留按程序及参数直接执行的行为；需要 Bash 语法时，可显式调用安装的 Bash 可执行文件。命令工具遵循现有权限模式；自定义允许规则需使用新的工具名称，旧工具的询问与拒绝规则仍适用。

插件独立发布，不属于 Nexus 本体的交付内容。Nexus 提供插件宿主接口、管理页面和公共 UI 资源；插件程序、SDK 示例、手机端 APK 及其构建验收由各自的发布维护。仓库中 `mobile-bridge/` 的既有资料不构成 Nexus 本体的安装或测试前提。

公共插件 SDK 1.2.0 提供 `work` v1：插件可独立启动标准后台工作，读取状态和事件，暂停／恢复／取消所属工作，并选择静默完成或向主交流回报。执行沿用 Nexus 的工具、权限审批和项目协调；业务调度与条件留在插件。接口、Python／Node 示例及旧入口兼容说明见 [插件 SDK](nexus-plugin-sdk/SDK.md)。使用新能力的电脑须更新并重启实际运行的 Nexus，再导入插件；插件 ZIP 不包含宿主更新。

旧定时与重复安排、网页监听、长期交代、自由唤醒、每日回顾、静默经历、专门人设管理及静态记忆原型已退出本体日常业务。[约定与关注](plugin-dev/followup/README.md)是独立安装的新插件，通过公共 `work` v1 接口使用现有后台工作，提供时间与指定工作事件触发；不恢复旧数据或自主活动执行器。普通独立会话和手动新建任务退出入口；工作由主交流承接，也不提供独立通知中心。相关研究资料按计划独立归档，旧代码可通过 Git 历史查看。

本轮不以模型调用费用或配额限制行为。上下文窗口与协议要求仍按实际模型能力处理；这些限制不代表费用预算。

## 数据与配置

```text
config.json              模型、当前工作目录、项目历史与运行设置
credentials.json         API 凭据
owner-instructions.txt   所有者原则与交流偏好
owner-instruction-items.json  图形界面中的指令条目边界（正文仍以 txt 为准）
roles.json               所有者修改的三个角色规则
sessions/*.jsonl         主交流原文、工具记录、摘要检查点及适用的原生续接信息
tasks.sqlite3            工作、父子归属、历史与检查点、操作、结果事件及主交流输入队列
attachments/             按交流和工作归属保存的原件与提取文本
model-requests.sqlite3   实际模型请求记录（按现有保留策略）
plugins.json             普通插件状态与设置
hooks.json               钩子及订阅的启停偏好
plugin-events.sqlite3    普通插件事件与订阅
plugins/<id>/            普通插件运行资料
archive/convergence-*/   本轮迁出的研究业务资料与读取说明
```

模型协议标识分别为 `anthropic_messages`、`openai_chat_completions`、`openai_responses`。思考强度可使用提供商默认或 `low / medium / high / xhigh / max`，实际支持取决于服务端。

模型配置可填写 `context_window_tokens`；本地上下文窗口按全局 `context_limit`、模型窗口、64,000 的顺序选择，仅用于请求容量管理，不会扩大服务端真实上限。

凭据、研究原文和运行记录属于所有者；导出或处理数据时保留目录和关联。不要把凭据写进 Git 或日志。

## 开发与测试

安装开发依赖后，在仓库根目录运行：

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe -m pytest tests -q
node tests/frontend_behavior.cjs
```

前端定向检查使用 Node 内置模块执行实际脚本和模拟接口，覆盖发送附件、回复期间补充输入、任务审批与详情保留、实时连接恢复和宿主插件配置。需要 Node 22+，不需要 npm 依赖或真实模型。Python 修改优先运行受影响的测试文件；仅在改动范围或失败证据需要时扩大验证。

测试覆盖范围、通过数量及真实模型验证情况会随版本变化；请以当前测试运行结果为准。自动化测试通过不等于所有功能已经完成实际操作验收。

## 开发区与发行区

当前 Git 仓库作为开发区，独立的 `../Nexus-release/` 作为发行区。发行区位于仓库之外，
不创建或复制 `.git`，不受开发区 Git 跟踪。更新发行区时，只从已提交版本复制 `nexus/`、
`start.bat`、`pyproject.toml`、`LICENSE` 和 `.gitignore`，并将
[发行版说明](docs/发行版README.md) 放为发行区的 `README.md`。

保留 `nexus/` 中运行所需的网页、字体、第三方库及各自许可。发行区不放 `docs/`、
`tests/`、独立插件或手机端发布包、开发工具、虚拟环境、构建缓存、模型配置与凭据、
会话、附件和其他运行数据。发行区用于对外复制，实际使用后生成的数据不再属于干净
发行文件；再次发布时从开发区的已提交版本重新整理。
