# 约定与关注 0.1.0

让灵在约定时间或指定后台工作发生变化后执行任务。安排、背景、上次结果和每轮记录保存在本地；实际执行复用 Nexus 后台工作和权限机制。是否值得汇报、是否已经达成目标由模型判断。

## 使用

在插件管理导入 `nexus-followup-0.1.0.zip` 并启用，随后直接交代：

- “每个工作日上午九点整理这个项目的改动，每次给我一份报告。”
- “每两小时看看这个项目有没有正式新版，有值得关注的变化再告诉我。”
- “等这项调研工作完成，结合它的结果整理实施建议。”

可以通过聊天或「约定与关注」功能页创建、修改、暂停、恢复、删除和立即运行。列表显示当前状态、下一次时间、上次结果；运行记录中可查看本轮关联工作与工具记录。切换触发方式后点击「更新触发字段」。页面通过操作和手动刷新更新，关闭页面不停止安排。

支持单次日期／延迟、固定间隔、每天、工作日（周一至周五）、每周、每月指定日期或月末。每月 31 日跳过没有该日期的月份。日历时间随 Windows 系统时区；带时区偏移的单次日期表示固定时刻，固定间隔按经过的秒数计算。

事件监听只针对指定工作，支持完成、挂起、失败、取消、等待决定和遇到阻碍，可选择一次或持续监听。创建后只处理新事件。

保存安排不会立即执行。条件关注首轮汇报当前基线，之后按交代决定是否汇报；每次汇报模式始终报告本轮结果。详细记录保留，不把静默成功当成没有执行。项目、模型和思考强度在创建时固定，可以单独修改。

## 停止与恢复

同一安排不并发，运行期间多次触发只合并为一次待执行。最终受阻或等待决定时保留本轮并暂停未来调度。普通问题由灵尝试处理，不在每个工具错误后强行停止。

暂停／删除会同时请求停止当前工作，清除待执行标记；已有操作不撤销，历史不删除。可在「已删除记录」查看历史。恢复暂停安排时，若存在已暂停的关联工作，会继续该工作，仍需处理其审批或执行结果不明事项；不会重新创建一轮冒充恢复。

电脑休眠、服务关闭和插件停用期间错过的时间或事件不补跑；恢复后周期安排等待下个时间，过期单次安排标记错过。服务长时间未获得调度（超过 30 秒）按恢复处理。重启中断的工作保留记录并暂停，不自动重做。

## 配置与限制

需要包含公共 `work` v1 接口（SDK 1.2.0）的 Nexus、Python 3.12，以及可用模型。另一台电脑须先更新实际运行的 Nexus 并完全重启，再导入 ZIP；只复制插件或 SDK 客户端无法给旧宿主增加能力。保留该电脑原有的数据与模型配置。首次加载会在插件独立 Python 环境安装 `tzlocal` 和时区数据，需要网络。后台使用宿主已有的工具、MCP 和其他已启用插件；缺少工具、登录或授权时需先处理，创建安排不替代审批。

安排数据保存在 `<NEXUS_HOME>/plugins/followup/followup.sqlite3`。后台工作与模型请求仍保存在宿主原有数据文件。插件没有自己的模型密钥。

本版不包含外部 webhook、邮件／GitHub 事件、手机／系统通知、高级 cron、自主调整下次时间、旧业务迁移或关机执行能力。模型判断与外部服务结果仍需要通过实际使用核对；自动测试不代表所有网站和模型均已通过验收。

开发区构建：`.venv\Scripts\python.exe plugin-dev/build.py followup`。构建只生成 ZIP，不安装或启用插件。

## 开发验证

安装插件依赖和仓库开发依赖后运行 `.venv\Scripts\python.exe -m pytest plugin-dev/followup/tests tests/test_plugin_work.py -q`。浏览器验证使用 `node --test plugin-dev/followup/tests/frontend.cjs`，需要通过 NODE_PATH 提供 Playwright，默认使用本机 Edge；可用 `NEXUS_TEST_PYTHON` 指定 Python，用 `NEXUS_UI_ARTIFACTS` 保存截图。浏览器测试使用实际页面描述和隔离数据，不连接日常实例或模型。

本次实施的自动化、真实模型与实际限制见仓库 `docs/当前阶段/Nexus约定与关注插件v1实施与验证.md`。
