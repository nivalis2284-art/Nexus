# 前端接入记录 · 2026-10-29

把 `nexus-preview/` 的界面语言替换到正式前端，并接上真实后端。

## 替换范围

`nexus/web/` 现在只保留一套前端：

- `index.html`：预览版骨架，去掉预览控制标签；保留运行状态、昼夜、同步、更多四个入口。
- `css/ling.css`、`css/app.css`、`css/theme.css`：原稿画面语言 + 新页面样式 + 两套主题（灵青·朱砂 / 浅蓝·淡紫，各有明暗）。
- `js/core.js`：工具函数、弹簧、Markdown、主题表；不再带演示数据。
- `js/api.js`：新增，请求封装、快照映射、SSE 分发。
- `js/dialogs.js`、`chat.js`、`work.js`、`context.js`、`skills.js`、`plugins.js`、`settings.js`、`shell.js`、`boot.js`：界面与交互。
- 删除旧前端：`app.js`、`ling.js`、`tasks.js`、`context.js`、`skills.js`、`mcp.js`、`presentation.js`、`editing.js`、`navigation.js`、`live.js`、`app.css`、`context.css`、`presentation.css`，以及 `server.py` 里对应的静态路由。

`plugins.js` / `plugins.css` 保留：插件自带页面通过 `/plugins.js` 取宿主脚本。

## 接入方式

### 状态来源

界面偏好（视图、主题、动效、归属）留在 `localStorage` 的 `nexus-ui-prefs-v1`。
其余状态全部来自服务端快照，刷新即重读：

| 界面区域 | 接口 |
| --- | --- |
| 模型、提供商、强度、权限、工作目录 | `GET /api/state` |
| 交流记录、队列、请求、工作列表、用量、上下文占用 | `GET /api/ling` |
| 所有者指令、角色、自动组装段、历史摘要与消息 | `GET /api/context` |
| 技能 | `GET /api/skills` |
| MCP 服务 | `GET /api/mcp` |
| 插件与请求记录 | `GET /api/plugins`、`GET /api/model-requests` |
| 基本原则 | `GET /api/instructions` |

### 写操作

| 操作 | 接口 |
| --- | --- |
| 发送消息（含附件、图片） | `POST /api/sessions/{sid}/attachments` 上传，再 `POST /api/ling/input` |
| 停止 / 继续 / 全部挂起 | `POST /api/ling/stop`、`/resume`、`/pause-all` |
| 主交流审批与回答 | `POST /api/approval`、`POST /api/answer` |
| 工作内审批与回答 | `POST /api/tasks/{id}/interactions/{iid}/answer` |
| 删除 / 重发 / 撤销交流记录 | `POST /api/ling/history` |
| 指令、角色、摘要 | `PUT /api/context/owners|roles|summary` |
| 技能增删 | `POST /api/skills`、`POST /api/skills/delete` |
| 提供商、模型选择、设置 | `POST/PUT/DELETE /api/providers`、`POST /api/select`、`POST /api/settings` |
| MCP 保存、重连、删除 | `POST /api/mcp/servers`、`POST /api/mcp/servers/{name}/reconnect|delete` |
| 插件加载、停用、卸载、设置、扫描、导入 | `POST /api/plugins/{id}/commands|settings`、`/api/plugins/scan`、`/api/plugins/import` |
| 文件预览 | `GET /api/workspace-file` |

### 实时更新

`GET /api/stream` 一条 SSE 连接。`scope=ling` 的事件直接驱动流式文字与工具步骤；
`scope=task` 的事件去抖后重拉工作列表。事件里的 `live` 是累计态，前端按
`message_id` 生成与持久化一致的 key，回合结束时只替换最后一条的节点内容，不整段重排。

### 映射约定

- 后端 `assistant.thinking` 拆成独立的「思考」条目，与处理过程折叠对应。
- 后端记录用 `index` / `message_id` / `tool_call_id` 生成稳定 key；乐观消息用 `pending:` 前缀，
  快照收录后自动移除。
- 工作列表来自 `task_summary`，详情（步骤、证据、记录、版本）在打开灵岛详情时按需拉取。
- 发送、删除、重发都需要先确认后端已受理；提交成功但快照超时不会回滚输入。

## 工作页分组与归档

工作页分成四段：**进行中**（常开，不折叠）、**已挂起**、**已结束**、**已归档**。后三段可以折叠，折叠状态记在界面偏好里，刷新后保持。

- 进行中为空时保留分组标题，下面给一行"现在没有正在进行的工作"的提示，页面结构不会因此塌掉。
- 已归档默认收起；归档卡片用更浅的底色与灰图标，与已结束区分。
- 已结束的卡片右侧是 `归档` + `⋯`（更多里放删除）；已归档的卡片右侧是 `恢复` + `删除`。
- 归档、恢复走 `POST /api/tasks/{id}/commands` 的 `archive` / `unarchive`；删除走 `DELETE /api/tasks/{id}`，带 `expected_version` 和 `confirm`，先弹确认。
- 卡片从 `<button>` 改成 `role="button"` 的 `div`，内部才能放操作按钮；整卡点击仍打开详情，操作按钮不会触发跳转，键盘 Enter/Space 也能打开。
- 首屏要单独请求 `GET /api/tasks?archived=1`，因为 `/api/ling` 只带未归档的任务。

## 验证

`tests/frontend_live_*.cjs` 用本机 Chrome 通过 CDP 跑真实后端：

- `frontend_live_smoke.cjs`：首屏、六个页面、上下文页签、主题与明暗切换、工作详情、灵岛概览、移动端。
- `frontend_live_send.cjs`：真实发送一条消息，验证流式、收束、用量与轮次统计。
- `frontend_live_work.cjs`：真实派发后台工作，验证列表分组、灵岛槽位、详情字段。
- `frontend_live_skill.cjs`：新建并删除一个技能，验证文件写入与列表刷新。
- `frontend_live_mobile.cjs`：390×844 下的横向溢出检查。

本轮结果：全部通过。真实回合的用量、上下文占比、工作结果、技能读写都与后端一致。

## 顺手修掉的问题

- 工作目录配置尾部多了一个引号（`H:\文档\LingNexus\Nexus"`），导致所有后台工作一创建就挂起。
  已通过 `POST /api/settings` 改回正确路径。
- 旧的挂起任务仍把带引号的路径写在自己的记录里，无法恢复；需要时在主交流里取消或重新派发。

## 已知限制

- 模型回合运行期间，`GET /api/ling` 可能被后端的会话锁挡住数十秒。前端给请求加了 20 秒超时，
  期间界面仍靠 SSE 增量更新；回合结束后会补一次快照。
- 工作列表接口不返回创建时间与工作目录，列表卡片显示最近更新时间；准确区间在详情里。
- 主交流的审批与回答链路已按接口实现，但本轮没有构造出真实的待审批场景，未做端到端验证。
