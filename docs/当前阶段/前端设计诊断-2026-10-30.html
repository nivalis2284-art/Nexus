Nexus · 灵 — 前端设计诊断

一个灵，
两种心跳

暖主题是颜料，冷主题是光。这本可以是这个产品最有意思的一点：同一个灵，在两种介质里以两种速度活着。但现在两套主题只是同一副骨架换了颜色——圆角、阴影、字体、材质、动效全部共用，只有色值不同。

于是两边都不彻底：暖的还没静下来，冷的还没活起来。纸墨不是错，错在它被当成了全站默认；灵动也不是错，错在它只活在三个组件里。两套主题，正好各认领一套语言。

01

Diagnosis问题不在审美，在"主题"只有一层

代码里 data-palette 切换的只是颜色变量：--jade / --cinnabar / --paper / --ink。切过去之后，圆角一样、阴影一样、字体一样、动效一样、材质一样。所以那不是两个主题，是两张皮。

  • 1

    两套主题没有两套语言

    主题应当至少包含四层：颜色、材质、字体、动效性格。现在只做了第一层。于是暖主题只剩"米色 + 一颗印章"，冷主题只剩"蓝色 + 同一套静态布局"——都没有说服力。

  • 2

    尺度缺席，一切都显得"差点意思"

    12 个字号挤在 10–15.5px、步长 0.5px；控件高度 14 种；圆角 23 种；内边距 62 组。没有尺度，运动就没有参照物——同一个 320ms 位移，在 8px 的间距里显得拖沓，在 48px 的间距里显得仓促。

  • 3

    层级靠 0.5px 微差与灰度

    11.5 与 12、13 与 13.5 的差别读者感知不到，只能靠颜色深浅补。元信息又散在四角：用时、tok、上下文百分比、路径、保存位置。层级不清，视线就没有落点，再顺滑的转场也只是"滑过去"。

  • 4

    动效是入场编排，不是因果反馈

    31 段关键帧里绝大多数服务于"页面的第一秒"：切页 160ms 出场 + 480ms 入场 + 逐项 34ms 错峰，叠了 7 处模糊。而"状态变了"——工作从运行到等你决定——只有一次颜色切换。预算花在了最不该花的地方。

  • 5

    没有静止的基线，动也读不出来

    三个 50vw 光斑按 26/32/22 秒随机漂移，二十多个 orb 同相位呼吸。当一切都动，就没有"动"这件事。暖主题因此静不下来，冷主题因此只是"一直在晃"而不是"在反应"。

一句话：这套界面缺的不是设计能力，是给两套主题分别定义"什么算对"。没有定义，每个组件都会退回到"安全但无特色"的平均值。

02

Two languages暖是颜料，冷是光

这不是两个配色方案，是两种物理。颜料吸光、有颗粒、边缘会毛、落在纸上不动；光透射、有折射、边缘发光、永远在变。把这条差异落实到 token 上，两套主题就各自成立了——而 DOM 一行都不用改。

这条分界还顺手解决了三件麻烦事：暖主题不必再假装自己很现代（它可以就慢、就静、就讲究）；冷主题不必再背着纸墨的包袱（它可以把玻璃、光、跟手做到极致）；而"灵动"作为产品性格被保留在两者共有的部分——灵岛、orb、连续形变、因果反馈，这些是灵的骨，不随主题变。

同一个生命，两种心跳：暖主题是静息心率，冷主题是运动心率。

03

Same component一个决策卡，两种活法

这是最能说明问题的一组：同样的内容、同样的 DOM，只因为主题性格不同，状态语言就完全不同。暖主题用"印"，冷主题用"脉冲"。

左边的印是对的，只要它只在暖主题里出现；右边的脉冲也是对的，只要它不跑到暖主题里去。现在的问题是两者混用：暖底上放着冷色的玻璃浮层，冷底上又压着一颗朱红印章——观感"不统一"的真正来源在这里，不在细节。

两种曲线

性格最终要落到时间上。同样是"一道内容出现"，暖主题该是渐入、减速、停稳；冷主题该是弹簧、到位、微过冲后落定。

暖 · 320msease-out
冷 · 220msspring

主题不只是"看起来不一样"，而是"呼吸节奏不一样"。用户切主题的那一刻，应该能感觉到时间变了。

05

Correct but anonymous正确，但没有特色

下面这些地方都没有错：结构完整、状态齐全、可访问性也在。问题是换掉 Logo 之后，认不出这是灵。两套主题的语言一旦定下来，它们其实都各有一个很自然的答案——缺的是"选一个"。

组件现在做对了什么为什么没有特色 / 两套主题各自该怎么做
工作列表项图标、标题、副标题、时间、状态色都齐默认的任务工具骨架，无法扫读。暖：一条静止的细线标出进度，像书页边注；冷：一条会流动的进度线，运行时有极轻的光流过。
设置行分组清晰，控件统一所有行等重，"立刻生效"和"要重启"长得一样。两套主题都该有风险梯度：即时 / 需重启 / 不可逆。
空状态有文案，不空白三页三种写法，都在解释"为什么空"。暖：一句留白得体的话 + 一枚小印；冷：orb 在地平线上呼吸 + 一个主操作。
处理过程折叠得当，带耗时把"做了什么"藏进灰字，把"用时 3.9 秒"放最前。应改为：三步轨迹在前，耗时退到页边。
消息头头像、名字、时间，规范灵在灵岛里是活的，到正文里退化成 22px 圆点。它该在你花 90% 时间的地方保留身份：暖用一个小小的印记，冷用一个会呼吸的 orb。
导航坞墨块滑动是全系统第二好的动效激活只是"变黑"，图标溶进底里。暖：像把一枚棋子放上棋盘（轻微下压）；冷：图标从墨块里"抬"起来（弹簧 + 反色）。

同一条 DOM，只改尺度与运动

左边是现在，右边只改了：圆角、阴影、一条会流动的进展线、一个右对齐的元信息列。结构一行没动。

07

Alignment眼睛对 20px 比 200px 更敏感

现在有三条互不重合的中轴：正文 720、输入舱 760、提示行 760+16px 内边距。落到 1440 宽的视口，左边缘分别是 402 / 382 / 398。

这解释了那种说不清的不适：不是"宽窄不同"，是"差点对齐"。差 20px 会被读成粗糙，差 200px 会被读成构图。而运动最怕"差一点"——参照系错了，每一次滑动都像在抖。

08

Motion共用的规则，分开的心跳

动效体系的基础很好——弹簧曲线是数值模拟出来的 linear()，有速度档位，也做了减少动效降级。这套引擎是资产。问题是它被用在了"页面进来的那一刻"，而不是"状态改变的那一刻"。

一个具体的数字：全局倍率 --motion: 1.35，设置里标的是 1.0x。用户以为的"正常"已经慢了 35%。

删

  • 切页的模糊 + 逐项错峰（每次导航最贵）
  • 卡片、请求卡、token 的模糊入场（7 处）
  • 三个光斑的随机漂移（无因果，还压文字）
  • 列表里每个 orb 的无限呼吸（20+ 实例）
  • 消息底部重复的"用时"

留

  • 灵岛形变（改成共享元素 morph）
  • 导航墨块的滑动（前缘先行、后缘追随）
  • goo 三点（全系统最灵动的东西）
  • 飞行液滴（保留，但要有去处）
  • 发送键进入可发送时的轻弹

加

  • 冷主题：指针跟随（光晕偏移 / 磁吸 / ≤1° 倾斜）
  • 冷主题：视图切换带方向与共享锚点
  • 两主题共用：状态迁移三拍（收缩 → 停住 → 外扩）
  • 两主题共用：数字只在真实变化时滚动一次
  • 两主题共用：流式输出只让"末行"淡入
场景属性冷 · 流光暖 · 宣纸曲线

共用规则五条：一次只动一个属性（不要同时转、缩、模糊）；位移不超过 8px；入场不做 scale（scale 只属于按压与磁吸）；列表错峰最多 4 项 × 24ms；超过 240ms 的动画必须可被下一次输入打断。

实现上不要把主题倍率并进 --motion——那是用户在调的"速度"。主题性格应该是独立的一层，比如 --temper: .8（冷） / 1.15（暖），两者相乘。

09

Sequence先删，再分家，最后才加动作

路径很清楚：先把两套主题从"换色"升级成"换语言"，再把多余的东西删掉，最后才谈新增。顺序反了，就会在错误的骨架上雕花。

P0

一天内 · 修硬伤 + 收敛尺度，零结构风险

七个野生色收进主题变量；修 theme.css:131 的 EOF、ling.css:252 的双重虚线、ling.css:345 暗色分段不可见；--motion 回到 1.0；字号 / 圆角 / 控件高度收敛到三档；正文、输入、提示统一 680 轴。

P1

两三天 · 让两套主题真的分家

把主题拆成四层 token：颜色 / 材质 / 字体 / 动效性格。暖：暖米底 + 纸纹 + 衬线标题 + 小圆角 + 极浅阴影 + 慢一拍；冷：近白底 + 玻璃浮层 + 无衬线紧字距 + 大圆角 + 两层阴影 + 快半拍。同一批组件，两套取值。决策卡在暖里是印、在冷里是脉冲。

P2

一周 · 让"活着"成为界面属性，而不是三处特效

灵岛改成共享元素 morph（orb 与标题不参与淡入淡出）；视图切换带方向与共享锚点；冷主题加指针跟随；orb 的三种形态对应空闲 / 思考 / 等待；处理过程与消息头重做，让"过程"可见。

已经对的，不要动

灵岛的形变、导航墨块的前缘先行、goo 三点的黏连、飞行液滴、发送键的轻弹、主题切换的圆形揭示，以及那套数值模拟的弹簧引擎——这些是灵的骨，两套主题共用，也是它区别于模板的地方。改造应该从"删"开始：把压在它们身上的模糊、颗粒、随机漂移和 0.5px 阶梯拿走，再决定这副骨头穿纸还是穿光。
