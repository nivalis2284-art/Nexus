## 本轮实际调整

- **任务输入回到运行层。** 新的 `runtime/input.py::accept_input` 由任务 HTTP 入口和灵的工作服务共同调用。移除“调用 HTTP 方法 → 回调收集响应 → 再取返回值”的绕行，输入校验、附件与图片能力检查、持久幂等接纳、暂停任务的既有继续语义由同一入口维护；灵追加说明仍明确不自动恢复任务，也不使待答审批失效。
- **MCP 启动只保留一份。** 普通聊天与任务复用 `runtime/connections.py::start_mcp`，各自拥有连接实例和生命周期。移除 Web 内的重复实现，以及没有调用方的 `TaskHTTP.status`、`add_task_message`。
- **普通聊天的临时审批状态收敛。** 每个 token 只保存一条“等待事件＋回答”记录，删除原来的三份映射及不产生实际效果的取消标志。未答复的统一空值在批准接口解释为拒绝、在问题接口解释为无答案；停止/断线仍唤醒等待者，任务的持久审批机制不变。
- **自主工作边界回到 Scope。** 组装器不再直接读取 `scope.runtime.store`、权限字典或目标内部结构，也不维护自主提示词、技能目录和 MCP 授权交集；由 Scope 提供边界与最新事实。删除临时配置包装，MCP 连接函数只接收服务器条目，不依赖配置存储。测试使用真实 Scope/运行时，移除为旧鸭子类型回退服务的伪 Scope。
- **修正获准技能交集遗漏。** 当前目录扩大到父目录时，保留旧行动已接受的多个子目录技能；未接受的同级目录仍不暴露，原授权不被悄悄扩张。父子目录交集由 Scope 统一处理。
- **监听客户端不再绑定服务端整份诊断结构。** 仅约束必要的规则身份/版本/状态、真实事件证据、epoch/游标顺序及租约健康语义，允许增加无关工具。配额统计、实现名、PID、诊断时间戳等可独立变化。事件来源、观察时间、内容、截断与观察间隙仍受校验，未因减法丢掉事实合同。原服务本就仅依赖标准库；实测清除 PYTHONPATH 后直接运行脚本可完成 MCP 初始化，因此未另造包或移动文件冒充解耦。

这些调整未增加插件框架、通用事件系统或新的产品能力；没有更改数据库格式、删除日常状态或放宽权限。需要保留的状态版本、未知外部效果、Token 准入和暂停归属校验仍按现有语义执行。

## 重要历史结果与边界

上一轮实现 A1：唯一灵主 Agent、有界自主审议、保底时间/真实变化/自主规划三源机会、持久目标与反馈、独立文本/Markdown MCP、页内持久消息、有限 Token 配额和所有者控制。关闭网页不停止服务端活动，退出服务会停止；无站外通知。较长工作仍由既有单 Worker 排队执行，不是多个任务同时运行模型。

真实补验已观察到“形成目标 → 委派 → 真正失败 → 读取反馈 → 修改后再行动 → 核对独立实跑结果 → 结束目标并发正式消息”。必须同时保留以下事实：

1. 初轮 68 次提供商请求报告 902,913 输入加输出 Token，曾因额度耗尽未能完成实际代码修复闭环；旧稿不能当成成功。
2. 第二轮新建独立测试 fixture，沿用真实旧失败资料；目标 `sensor240-indep-verify` 由灵提出，没有预写目标 ID。第一工作 `task_7792d628e1934457` 真实登记证据并 `task_finish`。
3. 灵最初错误地声称标准差/中位数没有算过；独立核验发现旧日志已有结果，灵随后纠正认识与正式消息。原始 240 行数据能运行，但两行 A 超限反例暴露另一处格式错误，保留该失败及修复后结果。
4. 后续工作 `task_40b9db3f4af44218` 写入修补，最终原数据、同一反例与边界数据运行成功，缺失文件仍按预期 exit 2。最后脚本 SHA256 为 `89ad7306b6ccf1fd4919caf13c5e9619cd6bdc2b27149f579487fe41bc9f4bfe`。第二工作在目标完成时仍等待额外 AST 审批，被关联目标控制取消，**没有第二次 task_finish**。
5. 第二轮有三次所有者显式提供真实测试反馈并给出审议机会；这些不是 MCP 自动变化触发。本轮没有新建监听规则，也没有实际到期计划。三源/MCP 证据来自初轮，初轮计划验证披露过 `+86400` 秒加速及一段受控轮询间隔。

- 监听客户端仍借用现有 MCP 传输的私有 `_request`，监听源码尚非独立发布包；已有独立进程和合同边界，本轮不为消除这个命名问题新增框架。
- 任务存储和 Web 入口仍较集中；本轮只拆掉有实际重复和反向依赖的部分，没有把大文件拆小后当成解耦。
- 自主暂停/恢复与持久任务控制需要区分所有者单独暂停、执行延迟退出、待答审批和未知外部效果。相关状态逻辑暂不压平；继续保留它的可靠性回归。
- 轮询监听只覆盖快照，短暂变化、离线间隙与内容截断需要如实保留。更换实现不能凭新基线还原丢失的变化。

- 旧持续性验收遗留的边角状态约束、jobs 审计记录主键、通知噪音、交互回答排列、等待用户时调度与版本校验等问题仍属历史待复核项；本轮没有将它们逐一复现、修复或记为通过。原始问题与已修复 A–F 的区分保留在旧验收摘要和 Git 记录中。
