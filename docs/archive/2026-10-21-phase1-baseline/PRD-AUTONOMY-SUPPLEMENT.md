## 1. 需求

在保留主 PRD 交付目标的前提下，**确定方案 A 为后续设计主方向，并把已有研究从“可行的总体方向”推进到“足以指导 4B 正式规划的具体实现形式及取舍”**。重点补充：

1. **三类自主思考机会共存：** 时间保底触发、真实变化触发，以及**灵自行规划未来一天或一段时间内何时再次思考**。三者共同服务于同一个灵，而不是形成三个独立决策 Agent。
2. **自主观察与监听的可行性：** 研究灵是否能够依据自身目标创建、修改、停止观察规则，在监听对象发生变化时获得有来源的变化信息，并合理决定是否重新审议；独立监听 MCP、规则式监听、可选 Jev 初筛等均是**待比较的候选方式**，尚非已确认技术架构。
3. **方案 A 的具体落地形态：** 明确怎样利用现有 Nexus 主 Agent、持久工作、权限、状态和消息能力，形成真实可持续的自主闭环，说明需要保留与新增的系统责任、交互边界及重要难点。
4. **为未来能力替换预留合理边界：** 评估哪些自主性能力适合由 MCP、Skill、Agent 工具或可替换组件承载，哪些必须由 Nexus 保证连续性和所有者控制。**当前不要求建设完整通用插件系统，不为未知未来做大规模预制开发。**

本阶段优先保证最后呈现的自主行为、稳定性及可维护的演进空间；不以省 Token 或选用更多模型作为方案优劣的主要判断标准。

## 2. 背景与目标

所有者倾向采用 [RESEARCH §5 的方案 A](RESEARCH.md)：**唯一灵主 Agent ＋ 有界的后台自主审议 ＋ 可延续的关注状态 ＋ 现有任务执行及反馈**。它与正常对话共享关键经历和最终决策归属，不要求模型一直运行。**方案 A 的方向已选作增量研究基础，但报告中提出的具体数据库、调度或交付细节仍可根据新的证据调整。**

此前方案主要依靠定期回顾和变化触发给灵思考机会。所有者进一步希望：灵还能自主安排未来的回顾时间，避免所有活动时机都被预置的程序规则控制；并能够自主指定值得观察的外部事物、修改监听条件。

同样重要的是，LingNexus 的最高愿景要求**技术可更新而经历、连续性与所有者控制不轻易丧失**。如果把观察、目标形成、规划和全部决策辅助都紧耦合在 Nexus 内部，可能不利于将来更换某种技术；但为了“插件化”先造庞大框架，也会违背项目按需投入的原则。需要以当前自主性雏形为实证场景，找出**真正值得保持可替换**的最小边界。

本轮成果不是新一轮空泛理论综述，也不是立即编码，而是为正式实施做准备：Coding Agent 下一步能够解释**怎样接入现有源码、模块之间怎样交互、真实运行中怎样验证、为何选择这条路线及排除其他路线**。

## 3. 我的原话摘要

以下为所有者明确表达的意思摘要；疑问和设想不得被改写为已确定的实现要求。

- “我倾向于方案 A”；至于如何深入重新理解自身经历，愿意在后续记忆系统阶段继续解决，但本版自主目标与结果之间的最低连续性仍需成立。
- 希望在原有保底时间触发、变化触发之外，**增加灵在一天的某个时间段自主规划未来一天触发机会**的方式；三种机制可以共存。保底用于避免长期没有思考机会，变化用于灵活响应，自主规划用于体现时间选择的自主性。
- 询问究竟什么算“变化”、哪些变化值得触发；提出灵可以通过 Agent 工具或 MCP 创建监听脚本/规则，变化发生后先由 **Jev 判断是否超过阈值**再考虑触发。此为待论证的想法，不是 Jev 和阈值已被指定为必需项。
- 进一步提出优先考虑**把监听能力与 Nexus 分离**，借助现有 MCP 让灵自主修改监听规则；可以把它视作基础形式，将来按需扩展其他观察方式，但不要求所有变化都来自 MCP。
- 怀疑自主性的大部分能力是否都能以可替换组件存在；Nexus 不应无止境承载业务功能。希望利用成熟的 MCP、Skill、Agent 工具，并确保未来新技术出现时能够尽可能局部替换。
- 当前**不要开发一套完善的插件系统**，而是预留位置、考虑把非必要功能移出 Nexus 核心。
- 参考用户**本地部署的 DSH（DeepSeek Harness）**及公开资料研究插件架构，也主动寻找替代方案；DSH 值得参考但**不必照搬，也不能预设最优**。
- 当前研究仍应以产品最终达到主 PRD 的自主性体验为目的，**具体技术实现由 Astra 在调查基础上作出取舍**，不要用需求文档束缚可行的创新路线。

## 4. 对原话的理解

### 已明确的边界

- **方案 A 是基准方向，不是实现细节清单。** 可以改变内部接线、选用工具及能力边界，但不能不经所有者认可改回第二个对外自主 Agent、把目标变成预设提醒，或取消主 PRD 的两条行为闭环。
- **三种触发机会要能够共同作用且互不机械重复。** 计划时刻代表灵认为“到时值得重新考虑”的机会，**不等于届时必须启动任务，更不等于必须向所有者发消息**；真实新变化可以使既有计划提前、延后、改变或取消。
- **监听能力的价值是让灵主动决定关注什么。** 客观变化与“是否值得唤醒主 Agent”必须区分；重要事实、来源、授权/撤回信息不能因为可选筛选器给低分而直接丢失。
- **唯一灵主 Agent**拥有自主目标、是否行动和是否对用户交流的最终决定。Jev、监听服务、规划器均可提供证据或候选，不另设能够独立代表灵对外发言的主体。
- **插件化准备不等于插件平台交付。** 避免强制所有功能通过 MCP，不因“未来可扩展”就引入尚无实际使用者的复杂抽象；同时防止把重要经历、目标、消息和用户控制锁死在某个实现的私有数据中。

### AI 的暂定理解（须由 4A 复核）

- 可将**时间保底、灵自行安排、真实变化**理解为多种审议机会来源，由同一自主审议过程统一接纳；具体调度与去重方式、哪些时机值得触发，应由候选方案比较决定。
- “变化”可能包括 Nexus 内部任务结果、用户撤回/审批、已关注资料的更新及授权外部事件；**内部确定性事件未必需要绕经外部监听 MCP**。外部监听 MCP 是优先调研的候选形式，但不预定所有事件源必须采用它。
- MCP 主要负责能力连接；Skill 主要提供可装载的方法和工作知识；Agent 工具是灵的实际操作接口。三者可以组合，但不等于天然提供持久事件、注册/卸载、状态迁移及权限可靠性的通用插件框架。
- 若更换监听器、规划器、模型或未来记忆组件，Nexus 应尽量保持灵的关键事实与控制状态可读、可迁移、可追溯；**无法承诺未来任何未知技术都能绝对零修改替换**，本轮应提出可实际验证的最小替换范围。

### 仍需由研究或所有者明确的地方

- 未来一天的自主规划应给出怎样的时段/时间表示、何时可调整、哪些变化应即时触发还是仅保存待复核；均需方案证据，不由本 PRD 硬编码数值。
- 独立监听服务的运行宿主、持续性、变化送达方式、可监听数据范围，以及 Jev 评分阈值是否有可靠作用。
- 核心与扩展能力的实际划分、状态所有权与迁移方式；如果某种划分会显著改变产品能力、已有行为或授权范围，应由所有者确认。

## 5. 功能范围

### 本次补充对第一版最终产品提出的能力

1. **三种可共存的审议机会。** 灵在保底时间、其自定的未来回顾时间及获准的有意义变化出现时，均有机会重新思考；能基于新的事实对计划作修改或取消，避免就同一事项重复启动。时间负责提供机会，主 Agent 才决定实质行为。
2. **自主规划可观察。** 在不需要所有者逐条规定时间的前提下，灵能基于现有关注事项自主形成至少一项有理由的未来回顾安排，也能决定不安排额外活动；安排、修改、取消和到期后的取舍可以追溯。
3. **监听与变化机制有明确可实施取舍。** 调查灵自主建立/编辑/停止关注的最小可行形式，区分客观变化记录、重要性判断和最终决策，能处理重复、过期、丢失来源、无变化、撤回与重启等情况。是否把独立监听 MCP 作为本版必须实施的功能，**留待 4A 的可行性和范围评估后由所有者确认**；不预设 Jev 是唯一闸门。
4. **必要能力可演进。** 自主性实现应避免让监听、时间规划、目标生成策略、辅助判断等可变化的技术，成为整个 Nexus 的不可替换前提；在本版确实要接入的地方，提供合理清晰、最小化的替换/停用边界。任何当前无法替换或迁移的能力应如实记录限制。
5. **跨实现的重要状态连续。** 已发生的正式交流、实际行动、目标依据、重要变化和用户暂停/撤回不能仅因某个可替换能力停用就丢失或被无意重新触发。保留主 PRD 所需的最低连续性；完整记忆平台留待后续。

### 增量 4A 必须研究并交付（为正式实现服务）

- **方案 A 的可实施形态：** 对照 Nexus 实际源码，描述审议入口、三源触发、状态与证据、目标取舍、持久工作、结果回流、主动消息、暂停/恢复与主交流让行之间的**端到端交互**。明确哪些可复用、哪些是本版必须新增、哪些值得后移，并指出关键工程难点及验证办法。
- **变化触发的可行性判断：** 比较至少一个实用的监听实现候选（可以是独立 MCP，也可以有更好替代），说明监听生命周期、规则由灵如何管理、变化怎样可靠送达、是否需要 Jev/阈值及误判和漏判风险，区分 Nexus 内部事件与外部数据源。不要求为了比较而实施完整监听服务。
- **自主规划触发与三源协调：** 论证灵所定回顾时机如何形成、保存、兑现和变更，怎样与保底/真实变化协同；分析中断、暂停、重复与过期计划。
- **插件化边界与技术调查：** 先核对用户本地部署的 DSH 项目具体版本、源码和可用路径（**本轮 Chat 无法读取用户电脑上的 DSH，不能把公开仓库当作已经核对本地部署**）；再阅读其插件机制与官方资料，重点比较能力注册、生命周期、事件、依赖、卸载、状态归属和替换。与此同时检索其他成熟例子，至少比较**沿用 Nexus 现有 MCP/Skill/工具边界、借鉴 DSH 的内部插件能力、以及其他更轻量或成熟的扩展形式**中的有竞争力方向。不得因为 DSH 号称“万物插件”就照搬整个 Harness。
- **推荐与取舍：** 至少给出一个能用于 4B 的完整候选方案，并在有真实竞争路线时比较用户体验、代码影响范围、替换能力、实际状态迁移、风险与维护负担；明确推荐方案、放弃的替代及理由、依赖与验证路径。交付不应停留在“可以做成插件”或泛化架构图；也不要求在 4A 过度写死文件级施工步骤。
- **研究文档：** 在保留 [现有研究](RESEARCH.md)的前提下，新建 `docs/RESEARCH-AUTONOMY-SUPPLEMENT.md` 记录此次增量调研、事实/推断/未测边界与最终取舍；供用户确认后进入 **4B 原生计划**。涉及本地 DSH 无法访问时如实说明障碍，并用公开资料仅做候选研究，**不得伪称已经完成本地验证**。

参考检索起点（仅帮助定位资料，**不是指定实现**）：[DeepSeek Harness 官方架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[MCP 官方架构](https://modelcontextprotocol.io/docs/learn/architecture)、[Agent Skills 规范](https://agentskills.io/specification)、[OpenClaw 插件架构](https://docs.openclaw.ai/plugins/architecture)。研究时以实际版本、官方源码与本地证据为准，可查找其他更合适方案。

### 本阶段明确不做

- **不把本补充 PRD 变成重写整套 Nexus / 搭建通用插件中心的许可。** 不要求插件市场、全量热插拔、跨语言沙箱、通用事件总线或所有内建能力迁移。
- 不强制使用 DSH/Cordis、MCP、Jev、某一个阈值、独立进程、特定存储架构或未来所有能力必须插件化；外置与保留应有实际理由。
- 不增加第二个代表灵的主 Agent，不实现暂缓的常驻 Flash 或完整长期人格、长期记忆平台。
- 不把自主规划理解成“每天必须填满计划”，不把规则检测到变化直接等同“灵已有自主想法”，不把模型的文字推测当真实发生的外部事件。
- **本次只产出补充需求；交给 Coding Agent 后先做增量 4A 研究。** 未获新的实施授权前，不修改业务代码，不部署长期监听或自动付费实验，不抢跑 4B/5。

## 6. 验收标准

### 未来正式实现时的产品验收（补充主 PRD）

- [ ] 时间保底、变化与灵的自主安排均能作为有效审议机会来源，共同交由唯一主 Agent 判断；同一变化不会无理由触发三次重复行动。
- [ ] 灵在没有新用户任务的情况下，能根据真实关注事项自主选择未来回顾时机并解释理由；当依据变化、事项已解决或用户撤回时，可实际修改、跳过或取消旧计划。
- [ ] 有变化或没有变化的正反场景中，系统能清楚区分**观察到的变化、为何值得考虑、灵最终决定什么**；不因辅助模型误筛就不可追溯地丢失关键事实。
- [ ] 若最终方案采用独立监听能力，灵可以在授权边界内创建、查询、修改、停止至少一种实际监听；变化有可回取来源，跨合理的断线/重启可以追溯，暂停/撤回后不继续产生未授权自主动作。若 4A 论证不纳入首版，须经所有者确认范围并记录后续路径。
- [ ] 对实际纳入本版的一项可变能力，能展示**停用或替换后，正式消息、已有目标、证据、已生效的暂停/撤回仍被保留并正确解释**；不要求证明与未来任意未知实现兼容。
- [ ] 保留主 PRD 中自主联系正反例、非预写目标产生、行动及反馈影响后续判断、用户优先与真实模型/UI 验收要求；插件化或多触发机制本身不算自主性已经达标。

### 本次增量 4A 研究的退出条件

- [ ] `docs/RESEARCH-AUTONOMY-SUPPLEMENT.md` 使所有者能理解**至少一个具体可实施的方案**、端到端行为、Nexus 保留与外置的职责边界、三种触发协调方式及推荐理由。
- [ ] 对监听 MCP 的可行性、Jev 及阈值的必要性给出有依据的判断，明确未证实的技术假设和已知风险。
- [ ] 对本地 DSH 与公开项目作**事实和来源可核对**的比较；确认/缺失本地部署证据均如实记录，不把单一框架宣传当架构结论。
- [ ] 能解释当前为何不建设完整插件系统，以及后续替换某项实际能力时最重要的状态和数据如何保留；只列有依据的增量改造，不预定大规模重构。
- [ ] 明确供所有者批准的关键选择与仍需实验的行为质量问题；**研究完成不代表自主性产品已经实现、也不等于阶段 4B/5 自动获准启动。**
