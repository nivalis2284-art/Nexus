# PRD｜Nexus 任务生命周期、失败止损与持续恢复

> 状态：需求草案，进入阶段四 A 研究前使用。
> 建议位置：`docs/PRD.md`。若该位置已有上一轮 PRD，先归档旧版，避免覆盖历史。
> 本轮优先①任务状态、②失败止损、④恢复及其必需的任务管理；③经验积累和⑤多 Agent 协作扩展暂缓。

## 1. 需求

Nexus 应将任务作为可以长期保留的对象，而不是把工作进度完全依附于一次对话或一次模型运行。用户能够提前创建任务但暂不执行；手动暂停正在执行的任务，保留已完成工作、已确定方案、失败记录和剩余工作；同时挂起多个任务；关闭和重启应用后，仍可直接从原进度继续，而不必重新探索任务现场。

**默认：无限期挂起 + 用户手动恢复。** 不设计划时间时，任务一直等待用户通过按钮或自然语言手动继续。用户可对单个任务明确设置**定时自动恢复**，也可以选择**到时间等待用户确认后再执行**。这些是每个任务可单独选择的方式，而不是全局只能选一种形态。

执行过程中应能够区分操作已发生、结果已验证、仍未完成和结果未知；对没有新依据的重复失败及时止损，同时不妨碍合理的重试和正常轮询。

## 2. 背景与目标

Nexus 已有 Agent 循环、工具调用、会话记录、待办工具、停止操作等基础能力，但对话历史不等于一份可信、可跨重启恢复的任务状态。“模型停止调用工具”也不意味着用户目标已完成。

本轮目标是使 Nexus：
- **有进度**：看得见当前目标、已完成事项、已验证结果、阻塞和下一步。
- **能止损**：不会因为没有新线索还反复尝试同一种失败方法。
- **能暂停并长期保留**：暂停不等于删除；可同时保存多个任务。
- **能直接继续**：重新打开时继承重要事实、决定和方案，仅核实确有必要的变化或未知操作。
- **执行由用户掌控**：默认不自行恢复；定时自动恢复必须由用户对具体任务明确设置。

## 3. 用户原话摘要

> “中断后继续……重新打开后能保持当前状态，我手动点一下或者直接用自然语言说一声就能继续任务，不需要让Agent重新探索进度。”
>
> “我能够手动终止任务……终止后的任务不是直接删除而是保存状态并挂起在某个地方，可以选择未来在某个时间点继续任务。甚至可以同时挂起多个任务，以及提前制定任务但不执行。”
>
> “不应该只局限于某一种形态，而是应该允许挂起后不执行/定时执行/我手动确认执行等等。”
>
> **最新补充：“默认是无限期挂起+手动恢复，但是可以手动设置成定时恢复。”**

优先开发①任务状态、②失败止损、④中断恢复；③经验积累、⑤多 Agent 扩展暂缓。

## 4. 对原话的理解（必要歧义）

**任务生命周期**包含：待执行、执行中、挂起、等待确认、已完成、取消/归档等用户可辨认的状态。它们是产品语义示例，不强制采用某种内部状态机。

- **创建任务**：可以只确定目标和约束，不立刻执行。
- **暂停/挂起**：尽快停止后续动作，保存工作状态；不能承诺撤销已经生效的文件修改、网络请求或工具副作用。用户口中的“终止但保留以备继续”优先理解为“挂起”，应与永久放弃任务区分。
- **取消**：不再继续执行，但记录可留存；**删除**是单独操作。
- **完成**：以目标达成及已掌握的验证依据判断，不因模型回复“完成”自动视为全部验收通过。
- **恢复**：继续的是已保存的任务目标、执行状态、关键背景与下一步，而不是还原模型隐藏思维或外部进程内存。
- **多任务挂起**不等于同时并行运行多个 Agent。是否需要并行执行不在本轮自动授权范围内。

### 每个任务可选择的执行安排

| 模式 | 触发条件 | 产品行为 |
|---|---|---|
| **默认：无限期挂起** | 用户手动点击或说“继续” | 未收到明确恢复指令就不执行 |
| **定时自动恢复** | 用户为该任务明确设置时间与自动模式 | 在约定的运行条件下，到时自动开始/继续该任务 |
| **定时等待确认** | 用户设置时间与确认模式 | 到时进入待确认状态，用户同意后执行 |
| **先创建，暂不执行** | 用户创建任务 | 保留待办，未来再设安排或手动开始 |

用户可查看、修改、取消某个任务的时间安排。未设时间的其他任务不应因此被执行。

**需要在阶段四澄清的边界，而非私自决定：** 设定时间到达时 Nexus 处于关闭状态，下一次启动是自动补执行还是先向用户展示待确认？同一时间多个任务到期应如何安排？计划时间的时区与错过时间如何处理？这不意味着必须建设常驻服务、开机自启或关机唤醒。

### 失败止损

失败原因与处理措施应基于实际反馈：区分参数错误、环境缺失、权限拒绝、暂时性故障、结果未知和任务验证失败。重复工具调用不总是无效循环；判断重点是前提有无变化、取得了什么新信息，是否值得继续尝试。

## 5. 功能范围

### 5.1 三项核心能力的独立交付要求（①②④，均不可省略）

**① 任务状态与结果核对：不等于只有待办列表。**

- 对需要多步骤执行的任务，系统能够保留**原始目标与约束、已确定的方案/决定、主要步骤与进度、实际产物和验证依据、剩余工作及明确的下一步**。普通简单问答不必强制创建详细任务计划。
- 任务状态应区分：**尚未开始、执行/尝试过、产物已产生、结果已验证、受阻、结果未知、任务整体完成**等在产品上有意义的差异；这些是语义要求，不强制逐一设计为内部状态枚举。
- **模型宣布完成、工具返回成功、测试通过某一项，都不能自动互相替代。** 对可直接检查的交付结果，必须尽量提供实际依据；无法验证的部分明确标注，不虚称整项任务已经完成。
- 用户至少能在任务入口或会话中直观看到当前进度、阻塞和下一步，并能纠正不准确的状态。任务状态必须真实参与 Agent 后续行动，**不能只是前端显示的一张静态进度卡片**。

**② 失败识别与止损：不等于设置一个固定重试次数。**

- 将有意义的失败现象、已经尝试的办法、获得的新线索、已经排除的假设和仍然受阻的原因，关联到**当前任务**。不要求记录每一行重复日志或建设跨任务经验库。
- 当**同一前提下重复失败且没有新的事实或合理的新尝试依据**时，Agent 应识别停滞，优先检查错误原因、查阅已有实现/可靠资料、改变策略；仍无进展可暂停相关工作并明确汇报，不得无限盲试。
- **不要误伤正常执行。** 网络短暂错误的有限重试、后台任务状态轮询、带新证据的验证重试均不应只因次数相同而被强制停止；权限被拒绝时不能换工具绕过授权。
- 暂停后继续时，应继承当前任务已记录的失败原因与排除路线，不无依据地重走旧的错误路径。可以使用现有工具与模型判断实现，不预设自动诊断引擎。

**④ 持久挂起、恢复与延后执行：不等于保留聊天记录。**

- 任务可在**未执行时建立**，也可在执行过程中由用户主动挂起；多个任务长期保留且互不覆盖。**默认无到期时间、不会自动开始或恢复，直到用户手动操作。**
- 暂停后，应停止后续 Agent 工作并保留足以直接接续的**目标、决定、计划进度、必要上下文、已验证成果、错误与阻塞、下一步**。重开会话或重启 Nexus 后，用户可通过按钮或自然语言继续，而非重新通读整段对话、重新调查已确认方案。
- 恢复时应**沿用已确认内容，只核实确实可能变化或结果未知的现场信息**。不重放已确认成功的操作；对中断时结果不明的外部操作，应先核实、再行动。
- 每个任务可分别设置**手动继续（默认）／到时自动恢复／到时等待用户确认**；可以查看、更改、取消安排。设置某任务的时间不会触发其他挂起任务。定时执行不自动意味着后台永远在线或电脑关机时仍能唤醒。
- **挂起、取消、完成、删除**必须可区分：用户说“停止但以后继续”应保留挂起态，不得等同删除；“取消”不应使历史记录凭空消失。普通暂停不负责回滚已经生效的文件或外部操作。

**三项能力应真实联动：** ①的进度/证据为②判断是否取得新进展提供依据，也为④恢复提供工作上下文；②积累的失败信息应随④保存、重启和恢复。不得将三项分别做成互不关联的 UI、提示词或孤立功能。

### 5.2 本轮必须交付

1. **任务管理入口**：能够创建待执行任务、查看任务列表与状态，管理多个待执行/挂起任务，切换至目标任务；界面形式可从简，不重建聊天产品。
2. **任务进度与证据**：持有目标、已确认方案、主要步骤及状态、结果证据、未完成事项、阻塞原因与下一步。区分“工具调用成功”“阶段结果已验证”“整个目标达成”。
3. **用户控制**：有明确的暂停/挂起、开始/继续、取消操作；支持按钮和自然语言完成常见操作，二者应作用于一致的任务状态；目标有歧义时需要识别并澄清，不操作错误任务。
4. **跨轮和跨重启持久化**：正常关闭并重开后，多个任务和重要进度仍然保留，能够从已知进度继续。意外中断导致外部操作结果不明确时，先核实实际状态，不能直接把“未知”当“失败”重试。
5. **执行安排**：默认无限期挂起与手动恢复；允许针对某任务设置定时自动恢复，或到时等待确认；可修改和取消时间安排；不得让其他未安排任务自动执行。
6. **失败与停滞处理**：追踪有意义的尝试、错误和已排除路线；缺乏新信息时能够改用调查/替代路线或挂起并说明原因；继续任务时避免重走已确认的死路。
7. **验证与结果说明**：交付有实际操作意义的验证，说明已完成能力、已实测内容、限制以及待确认的产品选择。

### 5.3 本轮明确不做

- 不扩展③跨任务自动经验学习与记忆体系；不扩展⑤多 Agent 并行、复杂委派调度。
- 不要求多任务**同时运行**；允许多任务同时持有和挂起。
- 不因定时恢复就默认为 Nexus 增加系统级常驻、开机启动、云端调度或关机唤醒。
- 不承诺恢复已经结束的操作系统进程、模型的隐藏思考、任意外部工具执行中状态，不建设通用回滚或 exactly-once 执行系统。
- 不要求大型工作流引擎、强制 planner/executor/critic 分工、向量数据库或缺少实际需求的抽象框架。
- 不擅自修改既有产品行为或扩大权限；具体技术路线由阶段四自主研究比较。

## 6. 验收标准

**验收遵循“能实际使用、跨重启仍成立、Agent 行为真正改变”的标准。** 不得仅因新增一个列表、一个暂停按钮、几行系统提示或有对应单元测试就宣布①②④全部完成。下面各项均需提供可观察的实际结果或适当的可复现验证；不能验证的明确写出边界。

### 6.1 逐项能力验收

**① 任务状态：**

- 给一项包含多个步骤和验证条件的任务，完成其中一部分后，任务页或会话能分别展示**已执行未验证、已验证、剩余、受阻**事项及相应证据；Agent 后续行动能正确使用这些信息。
- 故意让一个工具返回成功但最终交付物仍不符合目标，Nexus **不能把该工具成功误当整项任务完成**；没有依据时应明确说未验证或部分完成。
- 用户修正进度或目标后，后续执行采用最新有效信息，而不是继续使用过期清单。

**② 失败止损：**

- 构造连续的、**相同前提且无新线索**的失败。Nexus 能识别重复无效尝试，说明已经尝试什么，转向查证、换思路或挂起；不能仅无限重复同一种方法。
- 同时设置对照：允许有新错误线索后的合理重试、短暂故障重试及正常后台轮询，不能机械地将这些行为判为卡死。
- 挂起再恢复后，Nexus 应看得到该任务上次的失败尝试和已排除路线，不无故从同一死路重来。

**④ 挂起与恢复：**

- 执行多步骤任务，完成一些工作、确定某项方案并留下待办，手动挂起、退出 Nexus、重启并重新打开任务；无需重新分析整个项目，点击“继续”或说“继续这个任务”即可从**已知的下一步**推进。
- 创建三项不立即执行的任务，其中两项挂起且进度不同，第三项只保留计划。关闭重启后**任务和进度互不串线**，全部保持挂起/待执行；没有手动指令或显式时间安排不会自行执行。
- 给其中一项设置“到时自动恢复”，另一项设置“到时等待确认”，未安排的保持无限期挂起；分别验证到时行为，以及更改/取消安排的效果。
- 模拟外部操作可能成功但结果未收到的中断，恢复时先检查结果，不直接重复可能产生副作用的动作；暂停/取消也不能谎称回滚了已经生效的操作。

### 6.2 全局交付验收

1. **默认不执行**：创建一项任务但不开始，未设置计划时间；重新启动 Nexus 后任务还在，不会自己运行，只有手动开始或自然语言指令才运行。
2. **手动挂起和直接继续**：多步骤任务已完成部分工作时暂停；停止后续步骤并保存工作状态；重开程序，点击“继续”或说“继续刚才的任务”，能使用已保存方案、失败信息和进度推进未完成工作，不重新从头探索。
3. **多任务独立**：同时挂起 A、B、C，进度和安排彼此不混淆；恢复 A 不会丢失 B、C。
4. **定时自动恢复**：用户只给 A 配置定时自动模式，在约定运行条件下到时间 A 启动/恢复；无时间安排的 B 保持挂起。
5. **到时确认**：用户给 C 设置到时确认模式，时间到达后不直接执行，用户确认后才开始；修改/取消设置正确生效。
6. **自然语言控制**：用户可通过自然语言创建、挂起、恢复任务，效果与相应 UI 操作一致；若多个任务名称相似，应防止误恢复。
7. **失败止损**：故意提供无新增线索的重复失败，能够解释已尝试内容、识别停滞并合理改变处理；正常轮询或获得新证据的重试不被机械误停。
8. **完成状态可信**：步骤已操作、已验证和最终目标完成可区分；尚未验证的成果不会只因为模型表示完成就被当作已验证。
9. **中断副作用安全**：中断前存在结果不确定的操作时，恢复后先核实必要的环境事实，不盲目重放可能已经执行成功的动作。
10. **兼容与范围**：原有对话、权限、工具、Skill、MCP 和子代理功能不因本轮更改发生无依据退化；③⑤不被顺手加入。

### 阶段四需要解决的问题

- 如何与当前会话、`todo.write` 和存储对接，以免出现相互矛盾的进度来源。
- 何时保存检查点和关键操作证据，如何控制记录成本、避免失真的状态。
- 如何根据真实错误和变化识别停滞，不误伤正常重试。
- 定时触发在 Nexus 关闭、错过时间、并发到期等情形下的最小一致行为；哪些产品取舍必须交用户确认。
- 如何实现统一的按钮与自然语言操作，并保留已确认的授权边界。

**本 PRD 规定产品结果，不强制选择数据库、调度器、框架、存储格式或任务状态实现方式。阶段四 A 先研究并复核，四 B 再计划，五实施。**
