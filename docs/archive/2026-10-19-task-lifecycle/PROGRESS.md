## 当前任务生命周期交付

新增独立任务库 `tasks.sqlite3`，任务状态、工作步骤、证据、安排、运行认领、未知操作和待处理交互保存在同一权威库中；旧会话 JSONL 保持只读兼容，新任务消息不另写第二份 JSONL。任务执行由服务内控制器串行管理，网页关闭不再承担任务生命周期。侧栏提供创建/查看/开始/挂起/取消/重新启用、进度证据与一次性安排；自然语言可执行暂停/继续/取消、创建待执行任务和唯一标题任务选择。

## 关键实现与取舍

- SQLite 采用短事务和条件版本；文件变更改成同目录临时文件 + fsync + `os.replace`，文件读取的 SHA-256 覆盖完整文件；任务工具意图在派发前记录，未知结果不会被自动当作失败重放。
- 普通聊天仍保留原有请求流、会话 JSONL 和停止后台任务语义；任务模式使用服务内单一执行通道和独立持久事实，关闭页面不停止任务。
- 新任务等待审批/提问时保存待处理交互，回答时校验任务控制版本；普通聊天不要求等待结果跨重启恢复。
- 失败止损只阻止明确相同、无新依据的重复副作用；正常轮询、请求重试和记录新依据后的验证仍然允许。
- 不引入向量记忆、多 Agent 并行、系统自启/唤醒或完整工作流框架；新依赖仅 `tzdata`，用于 Windows IANA 时区支持。

## 未验证与遗留事项

- 真实模型对“任务进度、证据、失败前提”的长期使用效果没有量化对照；不把测试桩的表现当作模型能力验收。
- 强杀服务、断电、休眠和所有 MCP/命令副作用窗口的真实故障注入未覆盖；现有未知操作核查逻辑需要独立验收。
- 任务后台命令的 UI 主动刷新、停止和跨等待/重启输出尾部展示尚未形成完整手工验收路径。
- 普通聊天与任务执行共享执行容量的真实页面竞争、复杂自然语言在多次相似任务间的选择仍需操作验收。
- 旧会话不自动迁移成任务；仅历史聊天与新任务分开保存，避免双权威状态。

- 审批/提问回答后的工具续接已有实现和局部测试，但父工具、子代理及重启后单次执行的完整端到端链路尚未验收。

## 启动与独立复核入口

在仓库根目录双击 `start.bat`，或运行 `.venv/Scripts/python.exe -m nexus --no-browser`，然后访问 `http://127.0.0.1:8766`。

也可使用隔离目录启动，避免影响日常数据：

```powershell
.\.venv\Scripts\python.exe -m nexus --home .artifacts\acceptance-home --workspace . --port 8767 --no-browser
```

访问 `http://127.0.0.1:8767`。新数据目录需要自行配置模型；创建待执行任务无需模型。

1. 创建任务但不执行，刷新页面并重启服务，确认目标与状态仍在。
2. 配置模型后开始任务，核对步骤、验证证据和失败记录；确认普通一轮回复结束不会自动标记全部完成。
3. 手动挂起并恢复，检查任务命令停止、输出保留，以及已保存的决定与进度继承。
4. 分别设置定时自动恢复、定时等待确认；检查串行排队、修改和取消安排；关闭服务错过时间后，启动应等待确认。
5. 检查审批/提问等待、未知操作核查、取消后显式重新启用，以及删除任务不删除工作区文件。

这些是独立验收入口，未执行的真实模型及故障注入场景不计为已经通过。
