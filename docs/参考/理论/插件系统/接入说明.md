# 插件接入说明

本说明描述普通插件当前的接入方式；[实施与进度](实施与进度.md)是历史记录。理论见[插件系统理论](02-插件系统理论.md)。

## 交付与加载

插件位于项目根目录 `plugins/<id>/`，包含 `plugin.json`。插件管理可发现目录或导入 ZIP；清单须位于 ZIP 根目录或唯一的一层插件文件夹中。安装和扫描不执行插件；加载后才准备环境并启动资源，新插件默认不启用。

```json
{
  "id": "example",
  "name": "示例功能",
  "version": "1.0.0",
  "api_version": 1,
  "entry": "backend.py:create_plugin",
  "capabilities": ["context", "page"],
  "pages": [{"id": "main", "title": "管理", "path": "web/index.html"}]
}
```

`entry`、页面、服务和上下文均按需提供。清单的 `api_version: 1` 保持不变；下面的主交流接口是新增能力，插件应检查 `host.chat_api_version == 1`，不能仅凭清单版本判断宿主支持它。入口在宿主解释器内运行，并非进程沙箱。清单的 `dependencies` 或 `python_package` 用于准备独立服务的 Python 环境；本地入口使用标准库和宿主公共接口。

插件资料写入 Nexus 数据目录的 `plugins/<id>/`；卸载程序默认保留资料。`plugins.json` 保存启用状态和设置，`plugin-events.sqlite3` 保存普通插件事件与订阅。

## 生命周期与共同能力

入口工厂接收 `PluginHost` 并返回插件对象。`start()` 启动资源，`close()` 停止并释放插件自己的监听服务、连接和线程。直接主交流调用可在 `start()` 和 ready 状态使用；停用开始后不能发起新调用。宿主在等待在途调用结束前关闭该插件拥有的主交流订阅，以唤醒等待者；插件仍负责关闭自己的线程和监听器。`host.background(callback)` 用于有限的后台工作，宿主等待其租约结束，不能用于永久监听。

公开作者接口 `nexus.plugins.api` 还提供 `ToolSpec`、参数模型和 `PluginHost`。插件可按需实现 `tools(scope)`、`context(scope)`、`before_tool` / `after_tool`、`on_event(event)` 和页面操作 `call(action, values)`。上下文材料不会自动写入聊天；清单 `context_after` 可指定提供者顺序。插件 `skills/` 随启用状态参与后续请求。

`host.query()` 支持 `state`、`tasks.list`、`tasks.get`、`tasks.messages`、`tasks.operations`、`tasks.notifications`、`sessions.messages`、`sessions.records` 和 `ling.identity`。`host.command()` 支持 `task.pause`、`task.resume`、`task.cancel`；`work.*` 需要当前调用具有工作监督上下文。`host.subscribe()` 登记普通插件事件，例如 `message.saved`、`task.notification`、`task.owner_control`，与下述主交流实时订阅分别使用。

## 主交流接口

需要此能力的插件检查 `host.chat_api_version == 1`：

- `host.chat_snapshot()` 返回主交流快照，至少包含 `session_id`、`items`、`running`、`queue_count`、`live`、`live_revision`、`main_requests` 和 `tasks`。助手记录可带 `message_id`；将 `live` 按该标识与已保存记录合并，避免重复显示。
- `host.chat_send(text, request_id)` 沿用 `Application.submit_input` 的接收、排队和去重逻辑。重试同一消息复用 `request_id`，新消息使用新编号。
- `host.chat_subscribe()` 返回订阅，`get(timeout)` 返回事件字典；超时抛出 `queue.Empty`，关闭后返回 `None`。`close()` 可重复调用，订阅也可用作上下文管理器。

事件包含 `scope`、`owner_id`、`type`、`revision` 和当前 `live`。`delta` 的 `text` 是增量正文，`message_id` 用于关联记录；`thinking` 表示思考增量，`done` 表示本次输出结束，`error` 提供错误，`refresh` 提示重新读取状态。其他事件类型可能存在，消费者应按需处理。订阅接收整个运行时事件流（包括 `ling` 和 `task`）；调用方根据 scope 和 owner 标识选择主交流事件，并使用快照的 `live_revision` 与事件修订号协调状态。

订阅不重放历史：先订阅，再取快照；断线或重新连接后重新订阅并获取新快照。主交流记录由宿主持久保存，实时流不是持久日志。

## 独立服务与页面

清单 `services` 或 `host.connect_service(name, config)` 可登记 MCP 服务；命令中的 `{python}`、`{plugin}`、`{data}` 分别表示插件解释器、程序目录和资料目录。`model_tools` 明确列出供模型使用的工具；宿主可通过 `host.call_service()` 调用服务。纯 MCP 插件可用清单 `context` 和 `event_handler` 接入上下文及事件。

页面资源从 `/plugins/<id>/<资源路径>` 取得，在插件管理内打开；页面可向 `POST /api/plugins/<id>/call` 发送 `{"action":"snapshot","values":{}}`。需要打开原任务时，可向父页面发送 `{type:"nexus.open_task", task_id:"..."}`；返回主交流用 `{type:"nexus.open_ling"}`。关闭页面不停止插件。

独立服务可向 `host.event_url` 发送普通插件事件。插件事件与主交流实时订阅具有不同用途，不应假定它们重放主交流历史。

`live_revision` 是开始读取主交流快照前的保守水位；`live.revision` 可能更新。订阅方仍需处理水位之后的事件，即使部分内容已经出现在快照中，以免漏掉读取期间完成的回复。

事件可能已部分反映在快照中；优先按消息标识应用事件的完整 `live` 状态，或自行去重，不要无条件追加 `delta.text`。允许新增字段；调用方忽略不使用的字段与事件类型。手机接入插件 0.2.0 是可运行的监听服务与停用清理示例。
