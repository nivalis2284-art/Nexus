## 模块职责和依赖

| 模块 | 当前职责与主要协作 |
|---|---|
| `nexus/web` | 标准库 HTTP 服务和无构建网页；普通聊天请求装配 Agent，任务 API 将控制交给 runtime/task。`app.js` 负责聊天，`tasks.js` 负责任务视图与控制 |
| `nexus/runtime` | 任务串行执行通道、一次性调度、运行装配与持久化回调；复用 core Agent、工具目录与 task store |
| `nexus/task` | SQLite 权威任务状态、步骤/证据、操作意图、交互和安排；模型、HTTP、调度经其接口协作 |
| `nexus/core` | Agent 循环、上下文/压缩、权限、配置、请求重试、子代理；调用 model 传输与 tools 注册表 |
| `nexus/model` | 三种模型协议的请求转换、SSE 解析、流式事件与凭据传输 |
| `nexus/tools` | 文件/补丁、命令和后台进程、提问、任务工具等；统一参数准备与派发，执行权限由 Agent 控制 |
| `nexus/session` | 普通聊天 JSONL 历史、标题与原子文件操作；与 SQLite 任务消息分开保存 |
| `nexus/mcp.py`、`nexus/skills.py` | MCP 连接和工具发现、Skill 发现及加载，参与运行装配 |
| `nexus/bootstrap.py`、`start.bat` | Python 3.12 环境检查和启动，不承担业务状态 |

当前规模与需求没有证明更换框架、技术栈或重建架构的必要性。本轮采用局部修复，保留各模块既有职责。

## 已确认问题与修复

| 问题与实际影响 | 处理与验证 |
|---|---|
| 加载任务脚本后，聊天提交被无条件送入任务控制分支，普通文本和纯图片消息无法进入聊天流程 | 恢复普通聊天路由，任务控制只在文本控制路径处理；图片读取检查先执行；任务输入不能处理图片时明确提示并保留附件，不再静默丢弃。加载两个真实脚本的回归测试和真实 Edge 图片/审批链路通过 |
| 交互答案先写入数据库再检查 URL 中的任务归属；确认开始接口还未检查交互种类 | 写入前核对任务归属和交互种类，错误请求不改变其他任务审批或消息。新增 4 个回归场景，修复前均失败、修复后通过 |
| 任务页轮询遇到隐藏标签页或请求异常后不再安排下一次刷新 | 隐藏时保留刷新计时，暂时请求失败后重试，离开任务则结束轮询；前端行为回归通过 |
| 任务请求较慢时，旧响应可能覆盖用户刚打开的普通会话或另一任务 | 会话/任务视图共享请求版本，过时响应不再更新视图；回归验证旧任务响应不能覆盖新选聊天 |
| 任务每 1.5 秒刷新都重建交互回答和时间安排输入，未提交内容会丢失 | 同一任务交互/安排未变化时保留输入；实际服务端数据改变或切换任务时仍更新。前端行为测试通过 |
| 自然语言指令能够匹配唯一任务标题，却没有从指令中剥离标题，导致“继续〈标题〉”被拒绝 | 保留唯一匹配要求，匹配后仅识别剩余的明确短命令；新增回归测试先复现失败，再验证恢复目标正确 |
| 任务配置与步骤分两次事务提交，非法步骤请求被拒绝时，标题等配置已落盘 | 统一使用 `update_task` 的同一事务，复用字段验证；非法步骤/空值拒绝时配置和版本不变，合法组合同时保存 |
| Agent 丢弃模型停止原因，将输出截断或内容过滤也报告为正常结束；用量跨工具步骤和重试沿用旧值 | 保留真实 `finish_reason` 并清理每次响应的 usage；网页显示未完整结束，子代理工具保留部分文字同时标记失败，保留既有步数上限语义。真实 Agent 循环的确定性传输回归通过 |
| MCP 关闭时读取线程/管道未完整释放，等待中的调用可能等到超时；发送失败时遗留请求等待记录 | 关闭时唤醒等待者、回收进程与管道；发送/等待统一在 finally 清理请求记录。MCP/命令适配定向 **19 passed** |
| 恢复时再次保存整份模型历史，旧消息随轮次重复；中断时工具调用/结果可能不成对 | 只保存当轮 `agent.new_messages`，首次任务引导消息保存一次；中断未取得结果的调用保留明确 unknown。两轮/重开库的历史唯一性及工具配对回归通过 |
| 任务审批适配器是同步函数，Agent 却会 await 它，导致批准后无法正常执行；进入等待状态又推进版本，使当前 UI 答案被拒绝 | 改为异步批准适配器，等待转换与待答交互版本在同一事务更新，回答还核对当前任务版本。重开数据库后模型重新提交同一工具及参数，原授权消费一次，文件真实写入；更改任务后的旧审批仍拒绝 |
| 工具执行包装器和结果回调同时提交操作结果，造成一次执行两次落账 | 保留单一执行包装器提交结果，移除重复结果回调；审批恢复测试断言一项文件操作只产生一个 finished 事件 |
| 拒绝旧版本暂停/取消请求前，控制器已移除队列或触发停止 | 先持久验证并接受命令，再改变取消事件、队列与资源；回归检查拒绝取消不停止活动任务、拒绝暂停不丢失排队任务 |
| 部分停止/等待路径未结束运行认领；定时派发失败后安排可能卡在 claimed | 补齐认领结束；失败释放安排并允许同一安排后续重试，已成功消费不再派发；异常模型停止保留可见原因并挂起，避免正常结束误报 |
| 任务工具可凭另一任务的操作 ID 修改其结果核查 | 回调向存储传入所属任务并在写入前核对；错误归属拒绝且原操作状态保持不变 |
| 存在未用导入/局部变量、无作用分支、未接入的批量操作记录通道及历史投影方法 | 删除经调用搜索确认无使用的内容：批量 prepare/dispatch、空消息回调、重复结果包装、未使用的旧任务投影清除与最新答案接口，以及网页未用统计/序号；未增加兼容层或框架 |

并行任务：三名子代理均使用用户指定的 `DS/deepseek-v4.1-flash`、`high`，分别处理 runtime/task、core/model/session、tools/MCP/Skill/bootstrap。core/model/session 与工具组交付后由主代理整合；model/session 未发现需要修改的确定缺陷，不制造形式性改动。runtime/task 的中途测试暴露审批续接、版本和调度重试问题，主代理停止该子代理编辑后接管修复与最终验证，未以中途测试结果宣称完成。
