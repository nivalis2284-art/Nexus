# Preview module contract

Development notes for this isolated preview; no backend calls.

Scripts load as classic scripts in order: original motion.js (extracted by main agent), preview.js (shared API and chat/work), settings.js, extensions.js, context.js. Bootstrap after all load.

`window.P` API:
- `P.data`: persistent plain JSON object. Each module initializes its own namespace with `P.data.settings ||= seed`, `P.data.skills ||= seed`, `P.data.plugins ||= seed`, `P.data.context ||= seed`.
- `P.save()`: persist P.data in localStorage; errors shown to user.
- `P.esc(value)`: HTML escape. `P.icon(name)` existing SVG icon.
- `P.page(title, subtitle, body, actions='')`: returns `<div class="page">...` using existing page/card/button classes.
- `P.views[name] = function()` returns HTML for context/skills/plugins/settings.
- `P.render()`: render active management view (or chat if current view chat).
- `P.go(name)`: navigate to view.
- `P.action(name, handler)`: delegated click registration; buttons use `data-do="name"`, `data-id`, `data-index`, etc. handler(button,event).
- `P.dialog({title,body,submit:'保存',onSubmit(form,dialog),wide:false})`: opens shared modal with `<form>`, body string, footer cancel/save, inline `[data-error]`. onSubmit is async; return false to keep open; throw Error for inline error; otherwise dialog closes. For read-only set submit:null. Returns dialog element (for onchange etc). Form inputs accessible via `form.elements.namedItem('field')` or querySelector. Dialog supports nested layers and Escape.
- `P.confirm(title, text, onConfirm)`: themed confirmation modal (async callback supported).
- `P.toast(text)`: feedback.
- `P.field(label,name,value='',type='text',extra='')`: returns labelled input (HTML value escaped). Use own HTML for textarea/select, labels associated via nesting.
- `P.refreshModel()`: update chat model picker after settings changes.
- `P.running`: true while chat stream runs.
- `P.messages`: getter for P.data.messages, message {id,role:'user'|'assistant'|'tool',text,attachments:[],time,taskId?,compressed?}. Both main and context must access current array via P.messages getter (do not retain references).
- `P.editMessage(id)`, `P.deleteMessages(ids)`, `P.undoHistory()`: shared history behavior incl confirmation/lock/persistence.
- `P.setSummary(text)`: undo-aware history edit; context summary lives at P.data.context.summary.
- `P.data.undo`: last history snapshot or null; cleared on next user input. P.data.roles loaded by main agent from repo full role defaults (three {id,title,text}).

Styling: reuse ling.css tokens `--paper`, `--card`, `--raised`, `--ink`, `--ink-2`, `--line`, `--jade`, `--jade-ink` and classes `.card,.btn.solid,.btn.ghost,.fields,.field,.set-sec,.set-row,.page-head,.sec-h,.foot-note,.pill`. Additional style in module-specific CSS only. Use .stack (display grid gap 16), .row (flex wrap gap 10), .muted, .empty-state, .data-list, .detail-grid, .danger, .pre-wrap provided by main. All labels in Chinese. Theme and mobile responsive mandatory. User pinned attachment visual overrides skill taste bans.

Each module writes ONLY its assigned JS and CSS. No original files, HTML, shared JS edits. Never read credentials or real user runtime data. No fetch, backend, npm or real plugin installation. Local demo transitions and data should actually update.
