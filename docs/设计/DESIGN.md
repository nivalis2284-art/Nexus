# Nexus 前端设计规范

本规范是已确认的前端设计约定，适用于主交流、工作、上下文、技能、插件、设置、弹窗及宿主渲染的插件组件。后续开发先读本文件与[页面模板](页面模板.html)，复用实际代码中的参数，不自行重设一套风格。

## Overview

保留「灵玉／星枢 × 白昼／黑夜」、常驻可交互中枢、不透明卡片与追光。两套主题共用几何、排版、间距、入场节奏与交互规则，差别限于颜色、材质和背景场景。

固定数值的唯一代码来源是 `nexus/web/css/tokens.css`。组件使用语义变量；JS 从这份 CSS 读取 `N.DUR` 和 `N.MOTION`，不得在新页面重新填时长。现有业务行为与真实运行状态优先，不用装饰动画模拟进度。

## Colors

沿用 `theme.css` 的四套语义色，不另造局部主题。背景用 `--paper`，卡片用 `--card`，内嵌区用 `--raised`，正文用 `--ink`，次要说明用 `--ink-2/3`，边界用 `--line/line-2`，主要操作用 `--jade`，危险操作用 `--danger`。

卡片保持不透明；追光只画边界，复用现有全局实现，不能改变卡片内容颜色或覆盖按钮。主卡片、折叠卡片 summary 与直边、圆角均沿用 2px 追光边框，不再复制另一份渐变遮罩。

## Typography

保留现有字体家族：标题使用 `--font-display`，界面正文使用 `--font-sans`，代码及真实路径使用 `--mono`。两主题字号相同。

| 用途 | 参数 | 大小 |
|---|---|---|
| 元信息、时间、辅助标签 | `--text-caption` | 12px |
| 控件、字段标签、紧凑界面 | `--text-ui` | 14px |
| 阅读正文、消息、输入文字 | `--text-body` | 16px |
| 主卡片／分组标题 | `--text-title` | 20px |
| 弹窗／二级标题 | `--text-heading` | 24px |
| 管理页标题 | `--text-page` | 桌面 32px；手机 24px |
| 突出显示的真实数值 | `--text-metric` | 40px |

界面行高参考 1.5，长正文参考 1.75；现有 Markdown 标题、列表、代码行高按阅读用途保留。普通回复没有额外竖线；真正的 Markdown 引用块保留引用样式。不要为了追求黄金比例把正文、标签与代码全部按 1.618 倍递增。

## Layout

基础网格为 4px，尺寸使用固定档位：4、8、12、16、20、24、32、40、48、64、80、96px。不得在每个页面自由选择 13、17、19、22、26px 等布局间距。

| 场景 | 语义参数 | 桌面 | 手机（≤760px） |
|---|---|---|---|
| 主卡片／弹窗内边距 | `--card-padding` | 24px | 16px |
| 同级主卡片间距 | `--card-gap` | 24px | 16px |
| 页面分组间距 | `--group-gap` | 32px | 24px |
| 卡片内部子卡片／表单列间距 | `--inner-gap` | 16px | 12px |
| 一般行内容间距 | `--row-gap` | 12px | 12px |
| 图标、按钮组等控件间距 | `--control-gap` | 8px | 8px |
| 页面左右留白 | `--page-gutter` | 32px | 16px |

管理页继续复用 `.page`，最大宽度 960px；主交流继续复用 `--measure` 的阅读宽度及输入舱对齐轴。不要让表单、管理页和长文强行共用一个宽度。

黄金比例只作为适合场景的主次关系：宽屏的插件主从面板采用约 38.2%／61.8%，主内容获得更大空间；窄屏依现有断点转单列。对等的两列表单保持 1:1，不为应用黄金分割而破坏字段对齐。

圆点、细线、图标光学校正、进度条分段缝、开关轨道、导航指示器和背景轨道几何允许 1／2px 等明确例外。它们不属于卡片布局网格，不得将这些例外推广成新的间距档位。导航和滑块的内边距、指示器偏移必须成套调整，不能只改一个数。

## Elevation & Depth

保留现有 `--sh-1/2/3`：普通器物、交互抬升、浮层。两主题可通过颜色和阴影材质产生区别，但层级含义相同。不要新增无状态依据的闪光、呼吸或无限循环；运行状态、中枢和背景动效使用已有实现。

## Shapes

| 表面／用途 | 参数 | 圆角 |
|---|---|---|
| 行内代码、小切面 | `--r-inline` | 4px |
| 标签、小标记 | `--r-tag` | 8px |
| 普通按钮、输入框、小控件 | `--r-ctrl` / `--r-btn` | 12px |
| 主卡片内部的次级表面 | `--r-inner` | 16px |
| 主卡片、独立列表卡片、折叠卡片 | `--r-card` | 20px |
| 弹窗、输入舱、展开灵岛 | `--r-sheet` / `--r-composer` | 24px |
| 导航、分段切换外壳、紧凑灵岛 | `--r-pill` | 999px |

头像和圆形操作按钮用 50%；普通按钮不能因「圆润」随意改成胶囊。消息气泡复用 `--r-bubble` 的 20／20／8／20px，不重新发明尾角。内外相邻且确为同心的表面，内圆角随内缩距离减小；分离的控件按自己的语义档位选择，不能把所有内层都机械减成零。

## Components

### 结构与状态

- 卡片复用 `.card`、现有业务组件与语义变量。主卡片使用 `--card-padding`，相邻主卡片使用 `--card-gap`；内部紧凑行与子表面使用内部档位。
- 常规按钮高度 40px，小按钮 36px；圆形图标按钮、轨道开关等保持既有几何和命中规则。按钮需要清晰动作名、键盘焦点、禁用与忙碌反馈。
- 弹窗复用 `.sheet` 和现有对话框工具。模板里的演示控件不是业务实现；真实页面必须连接现有 API、保存反馈和错误提示。
- 所有宿主弹窗使用 `.sheet` 和 `data-size="small|compact|medium|large"`，尺寸仅来自 `tokens.css`，不得由业务 CSS 另写宽高。小档宽 480px、最高 60dvh；中小档宽 640px、最高 70dvh；中档宽 880px、最高 80dvh；大档宽 1120px、最高 88dvh。四档高度均随内容收紧，不强制拉伸；只有超过上限才在窗内滚动。弹窗限制在屏内，左右至少 16px，圆角统一 24px。
- 确认与项目创建／重命名用小档；项目选择用中小档；通用文本编辑、提供商、MCP、技能、钩子、插件介绍、插件运行状态及插件宿主生成的编辑弹窗用中档；文件／图片预览、插件功能页和插件管理放大窗用大档。通用编辑器按确认／编辑用途切档，不能按内容长短临时发明尺寸。
- 消息底部：正文至时间行 8px，时间与操作行间距 4px；时间 12px、行高 1.5，操作图标 16px、点击区 32px、按钮间距 4px。助手侧首个图标的 SVG 外框左缘与正文和时间对齐；用户侧末个图标的 SVG 外框右缘与时间和气泡右缘对齐，按钮居中留白通过操作栏向外偏移 8px 补偿。用户和助手共用 `.msg-foot` 两行结构，不能只对齐按钮盒子而忽略图标位置。
- 提供商模型编辑行：模型名、上下文、最大输出共用标签间距与 44px 输入高度；开关和删除按钮在输入基线上对齐。模型行间距、行内字段间距使用内部档位；手机模型名占一整行，两个容量字段对半，操作区另起一行。模型分隔线上下各留一个 `--inner-gap`；新增区沿用相同规则，父级已有 gap 时不叠加 margin。新增模型功能不得另写整组硬编码间距。
- 插件宿主组件继承同一套变量；第三方自绘 iframe 的内部布局不在宿主强制重写范围，接入 `plugin-ui.js` 的页面可读取这些变量。
- 插件管理详情固定高度为 `min(640px, 72dvh)`，标题与放大入口固定，正文使用主题化的内部滚动条。放大弹窗使用大档，沿用 `.sheet` 动效；放大和还原移动同一面板，保留设置草稿与滚动位置。启用状态使用现有 `.switch`，状态标签仅在左侧插件卡片显示。
- 插件状态行左侧显示在途调用／运行态／能力标签，右侧紧凑排列启用标签和开关，垂直居中；窄屏空间不足时允许换行。下方操作区左侧为重载／停止在途，右侧为查看介绍／卸载，组内按钮间距 8px、按钮高 36px；窄屏按操作组换行，不给单个按钮追加偏移来凑对齐。

### 动效

| 用途 | 基准 | 规则 |
|---|---|---|
| 页面退场 | 120ms | 复用 `N.DUR.micro`，旧页先退出 |
| 卡片、可见消息、弹窗入场 | 240ms | 复用 `N.DUR.enter`，减速到位，不回弹过冲 |
| 卡片错峰 | 24ms | 复用 `N.MOTION.stagger`，上限 8 个可见项 |
| 入场位移 | 8px | 复用 `N.MOTION.offset`，统一轻微向上到位 |
| 隐藏／恢复界面 | 220ms | 透明度过渡，侧栏和背景不动 |
| 新流式文字淡入 | 140ms | 仅新增文字；完成后回收临时节点 |
| 主题柔边波纹 | 850ms | 保留实时背景，属于明确的独立场景 |

标准档下，8 项入场最长为 `240 + 7×24 = 408ms`；加退场约 528ms。所有页面使用同一公式，不是每个页面各选一个时长。速度档位统一乘同一个系数，主题不再额外加速／减速。

页面导航复用 `N.stagger(view)`；面板内部替换复用 `N.cascade(panel)`；特殊布局可用 `N.enterItems(elements, viewport)`。根容器和子卡片不叠加播放同一轮淡入，嵌套卡片不双重编排，屏幕外历史不排队等待动画。数据同步就地更新，不能再次播放整页入场。进度条使用相同的 240ms／24ms 节奏，宽度不使用带过冲的弹簧。

灵岛外壳变形复用 `N.DUR.move`（标准档 240ms）与 `N.EASE_OUT`；宽、高、圆角和顶部位置同时到位，不使用尺寸过冲。窄屏收起态的宽度上限须随变形共同插值，不能切换状态时提前截断宽度；中途反向切换从当前可见尺寸接续，状态刷新不得叠加另一条宽度动画。

减少动态效果时取消位移和错峰，直接或短暂更新状态。流式接收节奏、滚动跟随和真实等待时间不冒充动画时长。输入框在布局外测量，只有行数变化时才改变高度，不能在每次输入时先设 `height:auto` 再撑回。

## Do's and Don'ts

- 新页面从[可运行模板](页面模板.html)和[接入说明](页面模板.md)开始，先找已有组件，后写业务特有样式。
- 圆角、间距、字号、时长使用变量与现有 helper，禁止复制一套硬编码值或在主题里重新定义几何与速度。
- 修改参数时同步 `tokens.css`、本规范及对应例子；需要新的档位时说明当前档位不能表达的实际场景。不要为了适配一张新卡片而悄悄改变全局尺度。
- 保留已确认的背景、中枢交互、不透明卡片、追光、主题波纹和主交流的滚动规则。视觉统一不授权改变业务行为。
- 验收至少核对两套主题的昼夜、桌面与手机布局；涉及输入、滚动或动画时做相应的定向行为验证。不要为纯样式变化主动启动全仓库压力测试。
