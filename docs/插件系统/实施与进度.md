# 插件系统实施与进度

日期：2026-10-23。理论依据：[插件系统理论](../理论/02-插件系统理论.md)。

## 执行边界

所有者批准分两阶段执行：

1. **本轮第一阶段：**完成开发、必要的针对性测试和影响功能的基本问题修复，保证逻辑闭环与代码完整。
2. **第二阶段：**所有者已明确授权，进行必要的针对性验收测试和收尾。不跑全量回归、压力测试，不自行切换日常实例，不以模拟测试代表真实模型验收。

新增校验或处理必须对应当前需求或实际问题，不为假设风险建设额外框架。

## 已确定的交付范围

- 五类接入能力：MCP、消息、上下文、宿主信息、插件界面。
- 根目录 `plugins/` 存放插件程序，支持文件夹发现与页面导入 ZIP。
- 统一插件管理页，提供加载、停用、重新加载、停止、卸载、设置与功能页面；插件功能统一从此进入。
- 同类插件安装更新不重新构建 Nexus，允许刷新或重启。
- 自主性业务完整迁入首个正式插件，包括定时、监听、预约、回顾、长期交代和自主反馈规则；灵的思考过程、通用任务和通知机制仍属宿主。
- 原资料、关联、暂停状态、反馈位置和自动活动开关延续；不重做已完成或结果不明的操作。
- 停用阻止新调用，单次在途操作收尾；卸载默认保留资料。
- 最近七天逐次模型请求可查看，包含实际发送内容、材料来源、插件参与与错误说明。

## 开发分工

主代理：共同插件管理、事件与活动、宿主接口、聊天/任务集成及整合修复。

DeepSeek 子代理并行负责：自主性插件业务与独立页面；插件管理界面；模型请求记录；插件环境与启动准备。必要的插件管理闭环测试另交子代理执行。

### 源码与入口

- 插件程序和启用状态由侧栏「插件管理」管理；插件功能页也从这里打开。
- 首个正式插件是 `plugins/autonomy/`，提供定时、公开网页监听、自主预约、活动记录、长期交代和结果反馈。通用任务、灵的主交流入口和通知仍属宿主。
- 数据目录里的插件资料、事件、模型请求记录与调度服务数据库，按[接入说明](接入说明.md)和 README 的记录位置使用。模型提供商编辑页可为每个模型填写上下文窗口；该值只用于本地裁剪和压缩预算，全局上限优先。
- 旧 `nexus/automation/` 和根目录 `services/scheduler/` 的部分源码仍留在仓库，但当前启动流程既不安装也不启动它们。它们只作为迁移背景，不能用来判断现行插件行为；源码归档工作的最终结果以主代理整合说明为准，本文件不提前记录尚未定稿的归档路径。
