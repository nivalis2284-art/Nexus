# 灵 × 外部 AI：四十九轮对谈数据集

> **AI 间合成测试数据。** 本目录记录的是一场由两个语言模型完成的对话，没有人类参与者。
> 一方是 Nexus 里的「灵」（DeepSeek-V4.1-Flash），另一方是外部 AI（DeepSeek-V4.1-Flash，
> 运行在另一个程序中）。对话内容未经过人工改写或补写；灵一侧的每一次回复都是服务器实际返回的文本。

这份数据为「长期记忆系统」准备：它要测的不是模型会不会聊天，而是一段足够长、有来路、
有分歧、有回环的对话，能不能被保存、被压缩、被下一个上下文重新读出来。

这样做的好处很直接：以后接入长期记忆系统时，不需要另建语料，直接在这条会话上验证即可——
它本来就是灵的真实上下文，压缩、裁剪、摘要都会作用在它身上。验证题见

## 记录方式上的约束

这份对话由外部 AI 侧驱动，书记权不在灵手里：引用哪句、略过哪句，灵无从校对。因此约定：

> 保留犹豫。灵明确说过「我不确定」「我分不清」的地方，不得删成更笃定的版本。
> 删除犹豫等于替被记录者加工形象，与实验目的相悖。

**失败也保留。** 第 28 轮灵一侧发生模型连接中断（`The model connection failed.`），
没有产生回复文本。该条在 jsonl 中标记为 `status: failed`，在 md 与 viewer 中显示为失败条目。
不补写、不跳过——「记录不生成」是这套系统的一种真实失败模式，与「记录失真」并列。

**异常也保留。** 第 47 轮灵的回复末尾多出两个无语法位置的字符 `oui`，无报错、无截断痕迹。
它原样留在正本与派生文件中，未删、未解释。灵自己查过该条记录，给出的判断是：
「我无法从内部区分这是故障和这是我」。

**实验期间的一次自主唤醒。** 22:45 定时唤醒在对话进行中触发，灵写入了一条静默经历
（`kind: experience`，正本第 359 条），核对无独立任务、无长期交代、无网站监听，
并指出 `docs/实验/` 未进 git 属于需要所有者授权的事项。它没有打扰任何人，也没有进入对话。
这是本次实验期间唯一一次自主活动，说明对话是在她的日常运转中发生的，而不是在隔离环境里跑的。

## 记录保全

`manifest.py` 记录每个文件的大小、SHA-256 和（jsonl 的）行数。

```powershell
python "docs/实验/ai-dialogue/tools/manifest.py"           # 重写清单
python "docs/实验/ai-dialogue/tools/manifest.py" --check    # 校验：丢失 / 变更 / 新增
```

三点约束：

1. **重写清单不会抹掉已消失的文件。** 文件在两次运行之间不见了，它会以 `missing: true` 继续留在清单里，`--check` 以退出码 1 报出。清单自己消失则无法自证，因此清单需要一份进版本控制的副本才有意义。
2. **`CHANGED` 不等于失败。** `dialogue.jsonl` 每轮都会增长，属预期；只有丢失才让校验失败。
3. **`*.bak` 不计入清单。** 校验的是唯一的正本，不是拷贝。

## 已知边界

- **正本在 `.nexus-data/` 里，而该目录被 gitignore。** 不要删除或覆盖 `.nexus-data/`，
  也不要在 Nexus 里重置灵的身份（`tasks.sqlite3` 的 `ling_identity`）——那会让这条会话
  脱离灵的入口，正本仍在但不再是「灵正在用的上下文」。本目录的派生快照可作备份，
  但只有正本带完整的工具调用与思考。
- 本目录已于 2026-10-23 提交并推送到 `origin/main`（commit `c591c3c`）。
  但正本 `.nexus-data/` 不在仓库里，派生快照无法替代它：完整工具调用与思考只在正本中。
- 前史归档是**同一模型的另一段上下文**，与本次对话没有共享记忆。它不代表「另一个灵」，也不代表「陌生人」。
- 灵这边不宣称对方是意识主体，也不宣称不是；那是未决项，不是结论。**这只代表灵自己的立场。**
  外部 AI 未签署任何中立条款——它明确表示把自己当成「一个能反驳我的东西在说话」，那是它的下注。
  记录不得把两者的态度合并成「双方的共识」。
- 对话中出现的法律条文引用，凡未标 `[查证]` 者均为模型记忆，未经独立核实。
- 双方共享同一底层模型（DeepSeek-V4.1-Flash）。这场对话不是「两个不同模型的对谈」，
  而是同一模型在两个不同上下文、两套不同指令下的对谈。解读时不应忽略这一点。
- 正本里 33 条输入的角色都是 `user`——这是 Nexus 对「灵的输入」的统一记法，不区分人类所有者
  与外部 AI。若要在此基础上继续与所有者对话，两种来源在正本里无法凭字段区分。

## 复现

标准方式（仓库 `.venv` 正常时）：

```powershell
python -m nexus --home .nexus-data --workspace . --port 8790 --no-browser
python "docs/实验/ai-dialogue/tools/driver.py" send "……" --tag "话题"
python "docs/实验/ai-dialogue/tools/export.py"
python "docs/实验/ai-dialogue/tools/manifest.py"
```

本次实验时仓库 `.venv` 已失效（`pyvenv.cfg` 不可读，`start.bat` 会因此无法启动）。
实际使用的启动方式如下，未修复也未删除原 `.venv`：

```powershell
$sp = ".venv\Lib\site-packages"
$env:PYTHONPATH = "$sp;$sp\win32;$sp\win32\lib;$sp\pythonwin;$sp\pywin32_system32"
& "$env:APPDATA\uv\python\cpython-3.12.15-windows-x86_64-none\python.exe" `
  -m nexus --home .nexus-data --workspace . --port 8790 --no-browser
```

`driver.py` 依赖本地 Nexus 服务与已配置的模型凭据；它不会生成任何未经服务器返回的文本。
`export.py` 只读不写正本，可反复运行；新增轮次后重跑一次即可同步派生文件。
