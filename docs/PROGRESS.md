## 1. 已交付的使用体验

默认进入统一的「灵」入口。灵拥有稳定交流记录与服务端持久输入队列，能够通过 work_start 发起独立持久工作并及时返回，随后继续交流，通过 work_list/work_read 了解工作，通过 work_message/work_control 补充要求、暂停、恢复或取消指定工作。任务完整执行记录不会无条件回灌主体。

运行中发送另一个问题进入队列，不隐含停止。主体交互由服务线程执行，网页断开不决定其生命周期；「停止当前交互」只停止当前灵回复，独立任务继续。旧普通会话和任务入口保留，普通会话沿用原流式与停止语义。

重要事件主动展开页内通知，不抢输入焦点、不切换会话、不清草稿。通知关联具体任务；审批和问题可直接在通知中回答，也可在原任务页处理。已读与授权分开，回答前重新读取任务与交互版本；已处理/过期请求不再作为可批准动作展示。离线回来可补看，普通工具输出与自动重试不逐条通知。

工作目标、步骤、决定、证据、消息、运行与未知操作继续由任务 SQLite 管理。主体按需分页读取历史和证据，长文本支持 text_offset 继续读取；任务工具增加 task_read，较早证据不再只能依靠最近 20 条简报取得。完成需引用存在的成功验证记录，并保存摘要、引用和未决限制。结构化约束不能独立证明任意模型的自报事实真实。

## 2. 工作持续、输入和恢复边界

| 场景 | 当前行为 |
|---|---|
| 灵收到输入 | 先保存内容、附件引用与请求身份，再由主体 Worker 有序处理；同请求重试不重复入队 |
| 复杂工作 | 经 work_start 创建并提交独立任务，立即返回工作引用；同输入/目标重试复用原工作 |
| 新的灵委派工作正常回复，但目标未完成 | 未阻塞、无待决交互、无未知操作且未被用户停止时有限继续；正常回复后最多续跑 4 次，连续 3 次续跑无保存进展时记录阻塞 |
| 旧手动任务正常轮末 | 保留原来的挂起行为，不自动改造成持续续跑任务 |
| 运行中补充要求 | 保存后在下一次父任务模型请求边界送入；游标区分待送入与已纳入请求，子代理不消费父输入游标 |
| 新附件 | 下一模型边界更新读取授权；交给新任务的文件保存任务自己的原件，不随源会话删除 |
| 等待审批/提问时追加消息 | 只保存，不创建新运行、不推进控制版本，原请求仍可回答；直接点击开始也不能绕过待决交互 |
| 通过灵修改已挂起工作 | 保存修改并保持挂起，明确恢复使用 work_control；原任务页「发送到挂起任务即继续」行为保留 |
| 暂停/取消 | 沿用任务自己的停止信号和后台进程清理，不回滚已生效操作；请求暂停与实际状态区分 |
| 多项工作 | 可以并存、保存、排队；任务模型执行为单 Worker 串行，主体交流独立。等待用户时已有后台命令可继续，不声称全部进程串行 |
| 重启 | 任务沿用中断核查与人工恢复；未开始的灵输入变为 held，需明确继续。处理中输入为 interrupted，核查已生效操作后发新消息继续，不整条盲目重放 |
| 完成 | 与模型轮次结束、工具成功、主动挂起、阻塞、等待授权和取消区分；持久完成状态产生通知 |

任务及子代理可使用 MCP、附件和普通工具，沿用任务权限、取消和审批通道。子代理不改父步骤或调用父 task_finish；工具操作有独立身份范围，避免父子复用调用 ID 时相互覆盖。结果保留停止原因、参数、有界输出和截断标记；授权等待保存部分轨迹，明确不冒充完整子会话恢复。子代理步数耗尽明确为不完整。

单次主体模型请求和已经开始的短工具动作仍有自然延迟，新的输入可以排队；耗时工作应独立委派。不承诺任意外部动作无损抢占或恰好执行一次。权限、明确暂停、输出/步数限制和未知操作优先于自动继续。

## 6. 重要取舍与修正

沿用研究方向，以服务端 SQLite 输入队列解耦网页与主体运行，工作仍使用 TaskController；页内轮询与持久通知满足已确认接收范围。三名 DeepSeek high 子代理分别负责存储/通知、执行器、网页；主代理负责主体桥接与整体集成。

为兼容旧工作，自动正常继续只适用于灵委派的新任务。多个任务可并存与排队，没有宣称任务模型真正并行。历史研究中“等待后台命令保留全部容量”与原源码有差异；本轮保持既有等待状态让出模型 Worker、已有命令可继续的行为，不冒称全部进程串行。

集成修正了待审批消息推进版本、直接开始使交互失效、重复委派与附件转交、脚本初始化、旧流抢回视图、输入重复/漏送、子代理误消费父输入游标、父子调用 ID 和同步审批返回值。子代理预算耗尽从成功改为明确不完整，相应测试按新语义更新，未删掉必要业务断言。浏览器桩曾将固定文字工具答复误当 JSON，核对真实接口后修正桩再完成联动。

## 7. 独立验收与遗留条件

使用原 start.bat 启动，默认进入灵。当前 Nexus 配置缺少可用模型服务地址/密钥，已告知用户；未通过 Nexus 做真实模型验证，没有输出凭据或复制日常会话。**PRD §6.6 的真实模型联合验证仍未完成，必须补做，不能由本地假模型替代。**

在 Nexus 配置实际模型、选择独立测试工作目录后，可复核：

1. 让灵独立开展包含多次调查、工具操作与验证的耗时工作；取得工作引用后连续询问无关问题和工作进度，核对原任务未被取消/重启。
2. 运行中补充要求并上传文档，检查待送入状态与下一边界读取；暂停后修改保持挂起，再明确恢复，核对目标、进度和证据。
3. ask 权限下触发写操作审批，先追加消息，再从通知直接回答；核对未批准不执行、拒绝不当作允许、普通草稿保留。
4. 等待决策时关闭页面、重启 Nexus，再补看处理；运行中断先核查已生效操作，避免重复外部副作用。完成后只有一次通知，重开仍能取回结果及较早证据。
5. 交付第二项工作，区分排队、运行、等待用户和后台命令；按需验证本机实际 MCP/Skill/子代理组合。

未验证：真实模型代表性复杂长任务、数小时稳定性、所有第三方 MCP/网关组合、断电时全部外部副作用。合理委派与证据真实性仍需真实模型和实际产物复核。完整长期记忆、人格、自主性以及页面关闭后的系统推送不属于本轮交付。

上传目录 .codex-remote-attachments/ 不纳入提交。本轮未改动用户日常配置、历史或凭据。提交与远端状态以 Git 为准。
