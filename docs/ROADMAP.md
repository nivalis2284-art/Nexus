## 当前优先阶段

**当前并行事项：持续性的独立全量验收继续；下一项产品探索工作明确为「自主性技术可行性预研」**。两者相互独立，不以预研代替持续性的验收。

- **为什么先做：** 没有持续交互、独立工作及可靠状态回归，复杂活动容易长期占用灵的交流；自主性也缺少合适的运行体验基础。
- **已交付的工程结果：** 默认灵入口、服务端持久输入队列、独立工作工具、任务记录按需获取、页内重要事件通知、历史及恢复保护。
- **仍需完成：** 使用真实模型、真实工具和实际界面验收复杂长任务、任务中闲聊、授权/阻塞/完成通知、恢复与结果真实性；不以本地假模型自动化验证替代。
- **持续性收口条件：** 独立验收报告给出通过或缺陷；不通过则回到修复与复验，通过后在阶段 7 更新产品业务、进度和路线图。
- **自主性预研可以先行：** 本次只进行研究与方案评估，不等同于批准自主性开发。研究完成后先结合结果澄清产品需求，再形成**开发型自主性 PRD**；是否进入正式 4A/开发，仍按既定工作流决定。

## 下一项明确工作：自主性技术可行性预研

**任务性质：** 现已整理为[研究型 PRD](PRD.md)（待用户确认）；本轮交付是研究报告，**不开发**。研究之后再确定开发型 PRD，不能自动进入编码；目前尚未启动 Codex 调研。

旧持续性阶段 [PRD](archive/2026-10-20-ling-continuity/PRD.md)、[RESEARCH](archive/2026-10-20-ling-continuity/RESEARCH.md)、[PROGRESS](archive/2026-10-20-ling-continuity/PROGRESS.md) 已归档，**持续性验收仍未最终通过**。

**为什么优先研究：** 仅有被动接收输入的 LLM、周期调用或已有 Harness 的任务自主执行能力，不足以证明灵具备用户所追求的自主发起、目标取舍和活动连续性；而长期依赖外部付费 API，如果不停调用强模型可能产生不可接受的费用。

**必须比较的路线：**

- 事件驱动/状态变化触发，闲时尽量不调用模型；
- 低频定时检查与按需唤醒；
- **候选：低成本小参数模型充当类似“潜意识”的判断层，必要时唤起主 Agent**（用户提供的设想，不是确定架构）；
- 无需小模型的轻量判定、规则/统计信号与其他成熟方案；
- 结合外部状态、已有经历及长期目标的自主活动路线，以及尚存的开放研究问题。

**研究评价标准：** 行为自主程度、目标和经历连续性、空闲与高负载场景的 API 消耗、漏触发/误触发、主 Agent 唤起成本、响应效果、安全和用户控制、对现有 Nexus 的可复用程度。小模型便宜不代表整体最省；需比较其持续检查、上下文开销和错误升级后的**总成本**。

**预期交付：** 有证据的候选方案对比、经济性/成本估算及可调整参数、难点与局限、一个或多个最小验证实验构想、未确认的产品边界；不直接规定最终架构、不进入正式编码。成本目标应可由所有者设置，具体金额/预算上限尚待讨论。

## 下一阶段：自主性的需求探索

### 已明确

- 灵不是只接受命令、被动完成任务的工具；自主活动是长期核心产品性质之一。
- 不预先限制为某种单一任务形态或只用于编程；在安全边界内应有充分的主动判断和行动空间。
- 可以自己发现值得做的事情、形成意图、决定开展或暂时不开展活动；不把定时自动生成任务当成自主性的唯一解释。
- 自主性与持续性分开开发，不顺势提前实现完整人格、长期记忆或自我进化。
- **长期经济性是核心约束：** 系统主要依赖外部付费 API，不能把长期高频调用强模型当作默认方案；活动自由度应与可承担的运行成本同时成立。

### 尚待讨论（不得写成已批准需求）

- 用户完全不在线、Nexus 页面关闭或服务不运行时，灵应当具备怎样的持续活动体验？
- 灵从环境、既有经历或内部回顾获得新行动线索的产品体验是什么？
- 如何判断某项自主活动值得开展、暂停、停止或放弃；如何体现有限资源与自主选择不行动？
- 何种活动需要事前确认、事后汇报或允许用户随时干预？如何保持安全而非机械性缩小活动范围？
- 下一轮自主性首个**最小但完整**的实际使用场景与验收结果是什么？
- 所有者可接受的日/月预算、偶发峰值支出、模型费用与自主唤醒频率之间的取舍是什么？
- 低成本模型“潜意识”是否有必要？应与事件驱动、无模型筛选和其他路线比较，而非默认采用。

这些问题在阶段 2 中逐个澄清。当前研究型 PRD 已起草，但未经用户逐项确认；不得标为「已确认」。本次研究不等同于下一轮开发授权。

## 未来候选与暂缓项

- **完整长期记忆、经历对未来行为的影响：** 是重要长期愿景，但不能因为持续性已建立工作事实存储，就冒称已实现。
- **人格演化和自主形成稳定倾向：** 所有者明确要求逐步推进，不同自主行动基础能力混为一谈。
- **跨模型同一性与底层技术替换：** 需要保护长期连续性和所有者选择权，具体机制暂不锁定。
- **无限递归子代理、多层指挥体系、常驻推理循环、复杂并发平台：** 都是潜在实现选项，未成为产品承诺；必要性由当时需求和研究证据决定。
- **性能与多工作并发：** 当前任务模型单 Worker 串行；实际体验提出问题后再确定是否进入单独需求。

## 路线图如何保持更新

1. **需求确认时：** 更新 PRODUCT 的已确认原则与本表阶段说明；在进入 4A 前由用户确认 PRD。
2. **实施与验收中：** 优先以 PROGRESS / 验收报告反映真实证据；这里仅同步阶段状态，不将测试通过等同用户验收。
3. **阶段收口时（工作流阶段 7）：** 对照已通过的用户验收与实际运行逻辑，更新 PRODUCT「当前已交付业务」、本表状态、遗留项与下一阶段优先级。
4. **新认识或纠偏时：** 可修改路线图与建议，不因历史投入锁死后续方向；需区分「所有者确认」「顾问建议」「未决定」。
5. **范围原则：** 不修改最高愿景文档，不把远期想法自动写入当前 PRD，不预制复杂技术计划。
