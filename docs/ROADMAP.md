## 当前优先阶段

**当前工作：** 持续性阶段仍由原 Coding Agent 按独立验收结论修复/复验；自主性阶段已依据所有者最新方向产出[开发型 PRD](PRD.md)草案，准备进入**4A 需求复核与可实施方案取舍**。两阶段不合并验收。

- **为什么做：** 现有 Nexus 可以接收并执行用户指令、管理持久工作，但尚不能证明灵在没有新任务时能主动形成目标、作出有理由的交流决定、用实际结果改变后续选择。
- **第一版预期体验：** 所有者长时间未主动联系时，灵可按真实理由主动联系或保持沉默；灵可根据已有经历产生非用户逐项指定的目标，自行调查、等待或放弃，并让真实结果影响后续行为。
- **当前优先级：** 先保证产品行为、可追溯的状态与用户实际体验，再考虑 Jev 等辅助判断以及 API 成本优化。只保留一个代表灵的对外交流与最终决策主 Agent。Flash 后台自由联想仍为未来暂缓项。
- **4A 应交付：** 阅读[旧研究型 PRD](archive/2026-10-20-autonomy-prestudy/PRD.md)、[主研究](archive/2026-10-20-autonomy-prestudy/RESEARCH.md)、[多模型研究](archive/2026-10-20-autonomy-prestudy/RESEARCH-MULTI-MODEL.md)与当前源码，提出至少一个可实施的**完整方案候选**；解释用户最终能看到什么、原理、真实可复用能力、关键风险、推荐理由及其他路线取舍。只有一个可行方向时应有排除其他方向的依据，不为凑数量制造方案。
- **下一步关口：** 用户确认关键产品取舍及推荐方向后，4B 用原生计划模式制定实施计划，再阶段 5 开发、阶段 6 独立验收。4A 研究报告不等于开发或验收成功；具体模型与架构由后续技术研究决定。

## 自主性预研归档

此前[研究型 PRD](archive/2026-10-20-autonomy-prestudy/PRD.md)、[自主性预研](archive/2026-10-20-autonomy-prestudy/RESEARCH.md)和[多模型补充](archive/2026-10-20-autonomy-prestudy/RESEARCH-MULTI-MODEL.md)均为历史证据，尚未对 Ling 的自主性雏形进行真实端到端测试。过去过度聚焦模型分工和成本的建议不能代替本次正式产品目标。

## 本阶段已明确与未决

**已明确：** 自主联系有时应沉默；目标必须来自可追溯经历而非机械预写任务；真实成果应影响下一次行为；唯一主 Agent 负责最终决策及对外交流；Flash 常驻思维暂缓；Jev 等候选不作为开发前提。

**仍待明确：** “长时间未联系”的体验边界、离开页面后消息如何送达、可观察的资料范围、哪些实际行动可以长期预授权、跨次活动的最低体验范围、是否需要 Jev。对会影响实际交付的问题，4A 给出有依据的可选取舍，其他技术参数无需所有者逐项决定。

## 未来候选与暂缓项

- **Flash 后台观察与自由联想：** 所有者认为普通 LLM 持续存在和思考仍是未解决的难题，原本采用 Flash 主要为了降低成本，故明确移至未来拓展；不能让它替代唯一主 Agent 对话或做最终决定。
- **完整长期记忆、经历对未来行为的影响：** 是重要长期愿景，但不能因为持续性已建立工作事实存储，就冒称已实现。
- **人格演化和自主形成稳定倾向：** 所有者明确要求逐步推进，不同自主行动基础能力混为一谈。
- **跨模型同一性与底层技术替换：** 需要保护长期连续性和所有者选择权，具体机制暂不锁定。
- **无限递归子代理、多层指挥体系、常驻推理循环、复杂并发平台：** 都是潜在实现选项，未成为产品承诺；必要性由当时需求和研究证据决定。
- **性能与多工作并发：** 当前任务模型单 Worker 串行；实际体验提出问题后再确定是否进入单独需求。

## 路线图如何保持更新

1. **需求确认时：** 更新 PRODUCT 的已确认原则与本表阶段说明；在进入 4A 前由用户确认 PRD。
2. **实施与验收中：** 优先以 PROGRESS / 验收报告反映真实证据；这里仅同步阶段状态，不将测试通过等同用户验收。
3. **阶段收口时（工作流阶段 7）：** 对照已通过的用户验收与实际运行逻辑，更新 PRODUCT「当前已交付业务」、本表状态、遗留项与下一阶段优先级。
4. **新认识或纠偏时：** 可修改路线图与建议，不因历史投入锁死后续方向；需区分「所有者确认」「顾问建议」「未决定」。
5. **范围原则：** 不修改最高愿景文档，不把远期想法自动写入当前 PRD，不预制复杂技术计划。
