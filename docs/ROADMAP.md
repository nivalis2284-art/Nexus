## 上一阶段方案：自主预约与每日回顾（工程验证已完成）

状态（当时记录）：隔离数据下，真实 Agent 循环、标准 MCP 连接与本地 HTTP 回调已跑通预约、到期唤醒原会话和同 ID 再改期；工作区 Python 回归 633 passed、1 skipped；仅含该轮变更的暂存版本另有 58 项针对性检查通过。跳过项为当时环境不支持目录符号链接的既有启动测试。模型响应使用可控模拟，不代表真实模型会稳定、合理地规划时间；未调用付费模型，未切换日常实例。该段保留上一阶段结果，不表示插件化第二阶段已全部验收。

自动唤醒时，灵需要同时考虑未来：如果某件事应在之后继续、检查或重新判断，可为未来保存一次醒来；普通聊天只在确有安排必要时这样做。新增独立 MCP 工具 `schedule_wakeup(title, reason, continuation, run_at 或 delay_minutes, id 可选)`，复用现有的一次性安排表。`run_at` 与 `delay_minutes` 二选一，后者从保存调用时起算并立即生效，目前不等待工作成功结束再开始计时。传入已有 `id` 会在同一记录上改期，删除继续使用现有 `schedule_delete(id)`。

过去的 `reason` 与 `continuation` 属于灵当时写下的旧计划。到点唤醒时，灵依据当前情况重新判断是否仍要做、应改变方向还是保持沉默，不把它们当成当前事实或既定命令。

间隔唤醒、每日时刻和开关保持不变；每日唤醒用于整体回顾，不强制排满，也不强制新建预约、任务或结构化决定。此次不新增数据库或页面，网页及其他事件监听范围不扩展。

## 下一阶段：局域网内用手机访问灵

目标是让手机与运行 Nexus 的电脑处在同一局域网时，可以直接打开灵的网页入口，延续日常交流、查看工作与处理重要提醒。日常实例仍由所有者控制，先取得真实使用数据，再决定后续功能。

当前服务固定监听本机回环地址 `127.0.0.1`，直接换成局域网地址并不能保证页面、接口与附件下载都可用。开始实现时需核对地址校验、静态资源、上传下载和启动提示中的本机地址假设，再确定局域网访问方式与手机端布局。第一版只解决同一局域网内的手机访问，不扩展到公网、账号体系或远程穿透。

访问范围扩大后，必要的登录与传输保护要与实际暴露范围匹配。具体方案在开始实现时确认，不把尚未发生的风险提前堆成通用安全框架。

## 后续方向：先取得真实数据，再验证设想

长期记忆、主干与分支、统一唤醒接口和 QQ 接入目前都是[设计设想](参考/外部接入-分支与记忆设想.md)，尚未批准实施。下一阶段先让灵进入日常随身使用的环境，积累真实的交流、工作和唤醒数据；这些数据是判断记忆是否真的能被找回、分支是否真的需要、外部接入是否真的有用所必需的基础。

长期记忆的研究材料仍见[人设、自我与长期记忆调研](参考/PERSONA-MEMORY-RESEARCH.md)，但现在不把某个外部记忆后端或数据库选型作为下一阶段任务。没有实际使用数据时，不以候选方案数量或调研结论代替效果验证。

长期记忆与“进化”仍然分开：记忆负责取回和引用，进化才负责在经历中改变人格与工作方式。人设 P3 的微调、人格向量或训练型自我模型仍是远期研究。

跨模型、跨实现迁移完整状态，所有者对发展方向的控制，以及长期成本与运行可靠性，继续作为贯穿各阶段的约束。
