## 1. 六大部分

所有者设想：LingNexus 由六部分组成。

| # | 部分 | 一句话职责 | 工程状态 | 验收状态 |
|---|---|---|---|---|
| 1 | **Nexus（枢）** | 承载 Agent 系统的核心：模型接入、工具、权限、会话、持久任务、网页入口 | **已交付**，持续维护 | 底座，无独立验收概念 |
| 2 | **持续性** | 灵在长时间工作期间仍能交流、监督工作、接收重要事件 | **已交付** | **未通过**：独立验收报告结论为"未通过"；A–F 六项已修复复验，未重新出具通过结论 |
| 3 | **自主性** | 灵在没有新指令时能自行形成目标、选择行动或沉默，并因真实结果改变判断 | **已交付**（A1） | **未通过**：阶段 6 独立验收未完成；长期联系质量、语义去重、数小时成本未实测 |
| 4 | **进化性** | 【待确认】 | 未开始 | — |
| 5 | **人设** | 【待确认】 | 未开始 | — |
| 6 | **记忆** | 【待确认】 | 未开始 | — |

**状态口径**：「工程状态」指代码已实现并通过工程验证；「验收状态」指所有者依据实际体验与可观察结果给出的通过结论。两者不互相替代——这是本项目一直坚持的区分，不因某次交付完成就改写成"已验收"。

## 3. 当前阶段：优化与重构（不开发新功能）

### 目标

所有者已明确：**不开发新功能**，转而根据现有功能做优化改进；其中一部分功能偏离了原意，需要重构。

### 为什么

前三个阶段是在"先做出来"的节奏下推进的，工程交付跑在前面，独立验收没跟上。现在需要回头处理两件事：把没验收的收口，把偏离想法的纠正。

### 本阶段范围

| 项 | 内容 | 状态 |
|---|---|---|
| 验收收口 | 持续性与自主性的独立验收尚未通过，需明确还差什么 | 【待确认】是否在本阶段完成 |
| 偏离纠正 | 部分功能偏离所有者想法，需重构 | 【待确认】具体是哪些功能、如何偏离 |
| 优化改进 | 在不新增功能的前提下改进现有实现 | 【待确认】具体范围 |

### 明确不做

- 不开发新功能
- 不启动进化性、人设、记忆三个部分（尚无具象需求）
- 不因重构而改变已确认的产品目标

## 4. 未决事项

以下问题影响本阶段范围，需所有者决定后才能写入正式 PRD：

- 【待确认】**"偏离想法"的判定标准**：是功能本身做错了、组织方式错了，还是做多了？三种情况的重构性质完全不同。
- 【待确认】**哪些功能需要重构**：需具体到功能名与偏离点。
- 【待确认】**验收收口是否属于本阶段**：持续性与自主性是否要在优化前先拿到验收结论。
- 【待确认】**进化性、人设、记忆三者的边界**：三者可能与"人格发展"重叠，需明确各自负责什么，否则无法拆分阶段。

## 2026-10-23：自主预约与每日回顾

状态：隔离数据下，真实 Agent 循环、标准 MCP 连接与本地 HTTP 回调已跑通预约、到期唤醒原会话和同 ID 再改期；工作区 Python 回归 633 passed、1 skipped；仅含本轮变更的暂存版本另有 58 项针对性检查通过。跳过项为当前环境不支持目录符号链接的既有启动测试。模型响应使用可控模拟，不代表真实模型会稳定、合理地规划时间；未调用付费模型，未切换日常实例。

自动唤醒时，灵需要同时考虑未来：如果某件事应在之后继续、检查或重新判断，可为未来保存一次醒来；普通聊天只在确有安排必要时这样做。新增独立 MCP 工具 `schedule_wakeup(title, reason, continuation, run_at 或 delay_minutes, id 可选)`，复用现有的一次性安排表。`run_at` 与 `delay_minutes` 二选一，后者从保存调用时起算并立即生效，目前不等待工作成功结束再开始计时。传入已有 `id` 会在同一记录上改期，删除继续使用现有 `schedule_delete(id)`。

过去的 `reason` 与 `continuation` 属于灵当时写下的旧计划。到点唤醒时，灵依据当前情况重新判断是否仍要做、应改变方向还是保持沉默，不把它们当成当前事实或既定命令。

间隔唤醒、每日时刻和开关保持不变；每日唤醒用于整体回顾，不强制排满，也不强制新建预约、任务或结构化决定。此次不新增数据库或页面，网页及其他事件监听范围不扩展。
