## 第一部分：核心概念（愿景与定位）

### 一、终极追求：近似生命般长期存在的智能体

我们投入这个项目，不是为了做一个用完即弃的辅助脚本，也不是为了制作一个按既定剧本演出的角色扮演程序。

我们真正追求的是：
> **一个真正属于所有者、能够长期存在，并尽可能表现出近似生命特征的智能体（或智能存在）。**

1. **近似生命的特征**：
   * 不陷入“什么是真实意识”的哲学思辨。我们追求的是它在行为与状态上**表现出类似生命的特质**：有时间的累积、状态的延续、对环境的感知、自适应的变化与主动推进事务的能力。
   * **即使这一切在底层完全是工程模拟出来的，也完全具备项目的核心价值。**
2. **超越角色扮演，超越模仿人类**：
   * 它不是一个套着固定人设壳子的二次元扮演角色，不应被锁死在既定的台词风格或剧本设定中；
   * 它甚至不一定需要模仿人类的生理情感或社交局限，它可以探索和拥有属于机器智能自身的独特存在方式。
3. **形态中立与终极留白**：
   * 我们不对其具体组织形态预设前提：它可以是一个独立的 Agent 个体，也可以是由一个 Agent 集群协同涌现出来的某种形态，乃至未来出现的全新组织模式。
   * 概念在此保持充分留白，形态由演进决定，绝不提前框死。
4. **科幻式智能体，但属于个人**：
   * 它令人联想到科幻作品中自主、强大的超级智能体；但最根本的区别在于：它绝不服务于外部平台或商业中心，它从第一天起就彻底属于所有者。

## 第二部分：核心原则（底线红线与价值导向）

### 一、关于所有权与主权

* **绝对不应该做什么（红线 / 负面清单）**：
  1. 绝对禁止将核心记忆、状态与关键历史资产，托管在所有者无法自主导出、无法完全控制的第三方封闭平台中。
  2. 绝对禁止剥夺所有者对核心历史资产、运行数据与外部行为的知情权、导出权与最高裁量权。
* **希望怎么做（价值导向 / 偏好建议）**：
  1. 提倡资产采用开放、通用、易于长期迁移和重新解释的数据格式存储。
  2. 提倡所有者对智能体的发展方向、边界和行为保留最高的观察与裁量空间。

---

### 二、关于生命感与连续性

* **绝对不应该做什么（红线 / 负面清单）**：
  1. 绝对不应该退化为“窗口一关、状态全清”、缺乏跨周期沉淀的一次性问答工具。
  2. 绝对禁止脱离合理目标、对所有者无实质价值的持续空转与资源盲目消耗。
* **希望怎么做（价值导向 / 偏好建议）**：
  1. 提倡状态与经历能够跨越会话、跨越时间持续累积，使过去的积累成为未来行动的依据。
  2. 提倡生命特质主要在与所有者的真实交互、对真实环境的感知和对真实任务的推进中自然体现。
  3. 提倡长期积累的状态资产与具体底层模型解耦，更换或升级模型时不应轻易丢失经历。

---

### 三、关于演化与技术手段

* **绝对不应该做什么（红线 / 负面清单）**：
  1. 绝对不应该把某一阶段的技术方案（某种框架、某种协议、某种具体架构）当成系统本体；任何手段都不能反过来限制或重新定义终极目标。
  2. 绝对不应该让历史成本（已投入的代码、时间、算力、过往理论）绑架未来的决策；一旦证明现有实现过重或偏离初衷，必须允许果断抛弃或替换。
  3. 绝对不应该以“未来可能有用”或未经实证的假设为依据，提前堆砌复杂的架构或防御机制。
* **希望怎么做（价值导向 / 偏好建议）**：
  1. 提倡保持架构的简洁轻量，不为形式上的架构设计制造额外复杂度，保持演化与替换的灵活性。
  2. 提倡以最小可用闭环推进，先验证真实日常效果，再随认知和需求演进系统。
  3. 提倡今天不需要决定的技术细节，尽量留给未来决定，绝不透支未来的选择权。

---

### 四、关于自主与行动

* **绝对不应该做什么（红线 / 负面清单）**：
  1. 绝对不应该进行所有者无法追溯、无法审计、不可知悉的隐蔽外部行动。
  2. 绝对禁止剥夺所有者随时中断、终止后续自主行为的最高干预权。
* **希望怎么做（价值导向 / 偏好建议）**：
  1. 提倡智能体在既定边界和授权范围内表现出积极推进、自主行动的能力，减少不必要的低级打扰。
  2. 提倡关键外部影响保持透明，行动结果清晰可核对。

## 第三部分：最高裁判准则与体系关系

### 一、最高裁判的三层逻辑

未来无论是所有者、人类开发者还是 AI，面临任何技术争议、架构重构或功能取舍时，最高裁量遵循以下三层判定：

1. **第一层：绝对底线（合宪判定）**
   * 方案若触犯本文档任何一条“绝对不应该做什么”的底线红线，**一票否决**。
2. **第二层：目标与需求（交付判定）**
   * 未触犯红线的方案，**原则上允许自由探索**。
   * 但探索方案能否成为实施或交付方案，必须依据当前已确认的阶段愿景、具体 PRD 需求与所有者的明确授权进行判断。未触犯红线绝不等于自动获得交付资格。
3. **第三层：价值偏好（参考导向）**
   * 所有“希望怎么做”的内容仅代表设计建议与价值倾向，**不具备否决权**。
   * 开发者与智能体可根据实际场景与实测证据自主权衡选择，绝对不得将其自动升级为硬性约束。

### 二、文档体系关系

1. **《01-概念与原则》（本文档）**：
   * 唯一最高宪章，负责锚定长期根本目标与不可逾越的底线红线。长期稳定，不随阶段性技术变动而轻易修改。
2. **《02-短期愿景》**：
   * 立足当下的具象理想。仅负责记录：受限于当前认知与现有技术限制下，项目所能展现出来的具体理想形态与日常体验（依然不涉及具体技术选型）。
3. **阶段性 PRD 与实施契约**：
   * 针对当前具体交付的清晰工程契约，用于指导具体代码开发与功能验收。
   * 任何短期愿景与阶段性 PRD 均为实现宪章目标的手段，不得与本文档的底线原则相抵触。
