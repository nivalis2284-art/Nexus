## 产品定位

**产品是什么：** LingNexus 是所有者长期掌握并可持续发展的个人 AI 系统。「灵（Ling）」是期望形成长期连续性、积累经历、能够行动和发展的 AI 个体；「枢（Nexus）」是赋予其模型、工具、运行与行动能力的系统底座。两者的区分是产品概念，不预设具体模块、模型或技术架构。

**主要解决的问题：** 超越传统「用户发起一轮指令—AI 执行—结束」的交互边界。希望 AI 的历史、重要状态和个体特征具备跨时间的连续性，能够与用户交流、开展活动、影响环境，长期不断发展；所有者始终掌握方向、重要资料与改变实现的选择权。

**主要使用者和场景：** 当前主要面向所有者自己的长期使用。先从与灵持续交谈、委派或管理复杂工作、接收关键进展开始；更远期探索不依赖即时指令的自主活动、长期经历与自我发展。

**重要定位：** 灵不是模仿人类或扮演某一种既定生命的角色；对其连续性、自主性和发展能力的追求是产品目标，不是对机器意识或生命本体的证明。

## 产品原则

### 已确认的核心方向

1. **连续性优先于固定实现。** 灵的长期同一性重在重要经历、记忆及人格的有意义连续性，而非某个固定模型、单一上下文或永远不变的行为特征。
2. **自主性不只是提高任务执行效率。** 灵最终应当能够在安全边界内自主形成目标、判断是否行动、开展活动，也能够选择不行动；不局限于等待用户布置任务。
3. **所有者掌握方向与边界。** 自主不等于越过权限、安全要求或无法干预；所有者保留调整方向、观察、纠正、迁移和重新设计的能力。
4. **对结果严格，对实现开放。** 不把子代理、主干分支、某种记忆方案或当前代码结构误当成产品目标；允许使用成熟外部技术。
5. **循序渐进。** 第一阶段明确拆分为「持续性」和「自主性」，分开探索、实施与验收；完整长期记忆、人格进化等远期方向不自动进入当前 PRD。
6. **长期自主活动必须考虑可持续成本。** 目前主要依赖外部模型 API，不以持续高频调用大模型作为默认前提。自主性研究必须同时权衡能力、延迟、误判、安全与长期资金消耗；不设尚未经所有者确认的具体预算数字。

### 当前已确认的产品边界

- 第一部分「持续性」：灵执行长任务时仍可交流；工作独立推进；繁杂日志不持续挤占主体上下文；可以监督、干预工作；需决策时主动询问，完成和真正受阻时主动简短告知。
- 在已授权目标内，灵可以自主调整工作方案；一般性操作不应频繁请示，但需遵守安全和权限边界。
- 第二部分「自主性」：方向已确认——允许灵在安全边界内自主行动；**具体使用场景、在线/离线活动形式、可承受的 API 成本与验收标准仍在需求探索中**，尚无已批准 PRD。
- **产品经济性要求已明确：** 灵的自主能力应当能够在所有者可承担的长期成本内运行；不能只证明理论上可运行，却默认长期无上限地消耗付费模型调用。自主行为可以选择暂不执行，不应为保持“活跃”而无意义请求模型。
- **唯一主对话主体（最新明确）：** 与所有者对话、代表灵作出最终决策和决定是否主动回复的是**一个主 Agent**。辅助模型可提供判断或信息，不作为另一个对外交流的灵；这不妨碍主 Agent 在既有授权内委派执行任务。
- **当前技术研究聚焦（并非已选定架构）：** 优先评估 Jev 一类快速决策模型辅助大量简单事件判断，再将必要信息交给唯一主 Agent 决定是否行动或回复；仍需与无模型过滤、仅主 Agent 等方案比较，验证效果、漏判和长期总费用。
- **Flash 后台思维方向暂缓：** 所有者原本设想的是用约 27B 的 Flash 模型在后台持续观察、自由联想或漫无目的地思考，**并非让它代替主 Agent 决策、执行或直接回复**。由于普通 LLM 怎样持续存在并有意义地思考尚未解决，且最初引入辅助模型主要为了降低成本，现明确放到未来探索；27B 是否足够也未实测。
- 现有的工作记录、持久任务或对话记录不等于完整的长期个体记忆；不要将工程实现声称为人格或意识已经产生。

## 自主性预研成果与下一步需求澄清

持续性的验收及必要修复按原开发工作流独立推进；自主性前置研究已形成[主要研究报告](RESEARCH.md)与[多模型补充研究](RESEARCH-MULTI-MODEL.md)。两份报告是研究成果，不代表自主性原型已验证或技术方案已批准。下一步在阶段 2–3 依据本轮纠偏澄清产品需求，再决定是否形成开发型自主性 PRD；不直接进入编码。

前两轮预研涵盖以下问题（作为研究历史保留，不自动视作下一轮开发任务）：

1. 当前被动接收输入的 LLM 与 Harness，能否在产品层面实现自行发现候选目标、决定行动/等待/放弃以及长期活动连续性？与尚未解决的内在动机、意识问题如何区分？
2. 低成本长时运行是否可行？比较空闲不调用、事件驱动、低频检查、小模型持续/间歇判断、多级唤醒以及其他合理方式。
3. **完整成本**应包括检查频率、每次调用输入与输出、上下文大小、摘要/记忆整理、误触发的主 Agent 调用、实际任务执行、模型切换与可能的基础设施费用。关注每日/月度及长期成本区间、成本上限、边际收益，而不是只比较单次 token 单价。
4. 自主性是否具有可观察的持续目标和活动依据？能否说明为什么决定行动或不行动？怎样避免空转、无限调用、误报、错误升级及资源耗尽？
5. 对照已有 Nexus 的持续性交互、任务持久化、审批与停止能力，提出多种不同技术路线和最小可验证实验，不预先锁定某种技术形态。

**候选设想及后续纠偏：** 最初提出低成本模型充当类似“潜意识”的候选；补充研究进一步比较 Jev、Flash 与主 Agent 的任务分配。所有者随后澄清，Flash 的原意是后台自由观察和联想，并非另一名决策者或对话者；继而明确暂缓这一难以实现持续思考的方向。**现阶段聚焦 Jev 辅助简单判断与唯一主 Agent**，但不把 Jev 当作已验证或必须采用的架构。旧研究文档保留原貌，不能把其中 Flash 可直接回复的技术建议误当成最新产品决定。

**预研产出与用途：** 已形成[自主性研究](RESEARCH.md)和[多模型补充研究](RESEARCH-MULTI-MODEL.md)，涵盖可行性、成本、风险及候选实验；其中部分模型职责与用户最新决定不一致，属于待纠偏的研究建议。后续如进入开发，应另行形成并确认**开发型自主性 PRD**，不可直接把研究建议转成实施要求。

持续性旧 [PRD](archive/2026-10-20-ling-continuity/PRD.md)、[研究](archive/2026-10-20-ling-continuity/RESEARCH.md)和[交付记录](archive/2026-10-20-ling-continuity/PROGRESS.md)已归档以供独立验收使用，**尚未宣布通过**。

## 候选想法（未批准开发）

- **自主活动：** 灵在没有用户即时指令时能否持续产生并推进自己的活动。已确认方向，仍需讨论典型情景、活动触发与可观察结果；尤其「用户未打开 Nexus 时是否继续活动」尚未确认。
- **当前优先候选：Jev 辅助判断＋唯一主 Agent：** 优先验证大量简单事件的判断是否可以低成本完成，复杂判断、决定是否主动回复及对外交流仍由主 Agent 负责；Jev 不是已确定的技术选型，需与更简单的方式公平比较。
- **未来暂缓：Flash 后台观察与自由联想：** 此前的 27B Flash 想法是类似闲时“瞎想”的内部活动，而非廉价版对话 Agent。持续存在和思考的机制尚未解决，现阶段不要求研究落实或实现，不否定未来重新探讨。
- **长期经历与记忆：** 重要历史能够长期积累、被重新理解，并真实影响未来表现。尚未制定当前阶段的交付范围。
- **人格与自我发展：** 随经历形成和改变偏好、倾向、自我理解及人格；所有者明确希望循序渐进，不提前与当前持续性需求混做。
- **跨模型与技术迁移：** 长期保护有意义的个体历史与所有者控制，不预先指定数据结构或某一种永久架构。
- **更多并行活动能力：** 现有多个复杂任务可并存和排队，模型任务执行仍串行。是否提升并发应由实际体验和新需求决定，不自动作为缺陷或下一阶段硬指标。

## 维护规则

- 阶段 1 由 Chat 与所有者维护产品定位和路线图；阶段 2–3 在明确用户目标后形成需求及 PRD；阶段 4–6 的研究、实现与验收由 Coding Agent/独立验收负责。
- **只有所有者明确确认的产品决定才能标记「已确认」；**研究建议、未定问题与长期愿景不得伪装成当前实现要求。
- 每个阶段收口（工作流第 7 阶段）及产品方向改变时，核对源码、[持续性记录](archive/2026-10-20-ling-continuity/PROGRESS.md) 和实际验收结论后更新本文与 [ROADMAP.md](ROADMAP.md)，不依据“代码已提交”直接改写成“已验收”。
- 本文记录业务与因果、状态，不替代详细 PRD，不重写受保护的愿景文件，也不要求未来技术路线遵循今天的形态。
