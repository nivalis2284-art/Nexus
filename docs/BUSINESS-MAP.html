    使用与配置

    用户进入系统、选择模型、管理自己的工作目录。

    • 会话与配置已验证新建、打开、重命名、删除会话；选择提供商、模型和思考强度；调整权限与工作目录。nexus/web/app.js · server.py · core/config.py
    • 对话与过程展示已验证文字与图片输入、流式回答、思考过程、工具步骤、用量和上下文提示。nexus/web/app.js · app.css · index.html
    • 人工协作已验证写文件、执行命令前确认；需要补充选择时向用户提问。core/permission.py · tools/ask.py · server.py::Approvals

    模型与 Agent

    把任务变成可执行步骤，再把真实结果带回模型。

    • 三类模型协议未验证Anthropic Messages、OpenAI Chat Completions、OpenAI Responses，支持流式事件解析与用量读取。model/gateway.py · _sse.py · _parsers.py · core/protocol.py
    • Agent 执行循环已验证判断是否调用工具、等待授权、执行、回灌结果；到达上限或停止请求时收束。core/agent.py · tools/registry.py
    • 上下文与摘要限制预算估算、裁剪工具结果、必要时请求模型生成压缩摘要；重载只从保存的会话记录重建。core/prompt.py · compaction.py · session/store.py
    • 重试与停止已验证在尚未产生可见输出时按策略重试；停止是检查点式请求，不强制中断已开始的文件操作。core/retry.py · server.py::_abort · agent.py::stop

    执行、扩展与数据

    工具、Skill、MCP 和子代理共享同一轮运行环境。

    • 文件与补丁已验证读、写、编辑、查找、Glob/Grep 与补丁应用；写操作可要求确认。tools/files.py · patch.py · _paths.py
    • 命令与后台任务已验证前台有界命令；后台任务按会话保留，可读增量输出、列出和终止。tools/shell.py · jobs.py · _jobs.py · _process.py
    • 待办、提问与子代理已验证维护任务清单；中断并询问用户；子代理独立运行，只把最终报告交回父级。tools/todo.py · ask.py · subagent_tool.py · core/subagent.py
    • Skill、MCP、网络工具限制Skill 正文按需读取；配置的 MCP 子进程工具加入注册表；网络工具只有配置后可用。skills.py · mcp.py · tools/mcp_tools.py · tools/web.py
    • 会话 JSONL已验证服务和用户消息、思考、工具调用及结果写入本地 JSONL；打开会话时重新构建展示与模型上下文。session/store.py · web/server.py::_persist · _transcript

    跨模块关系与连线含义

    每条重要关系都写明“发生了什么”；箭头方向就是信息或控制流方向

    网页 → 服务端 → Agent网页提交一条任务后，服务端加载会话、取出设置、规划上下文，并开始同一轮 Agent。服务端保持单运行锁；同一时间只推进一条任务。app.js send → /api/chat → serverHandler._run_turn → Agent.run
    Agent → 模型协议Agent 把系统说明、历史和工具声明按选中协议的请求形状发送；模型返回文字、思考、工具调用或错误信号。protocol.request_body → gateway.ModelGateway → _sse / _parsers
    Agent → 工具 → 模型需要行动时 Agent 调用注册表；结果连同名称、参数和成功状态回到对话，下一轮模型据此继续判断，直到完成或达到上限。Agent._invoke → Registry.execute → tool_result → 下一轮 request
    页面 → 会话文件会话列表来自 JSONL 文件；打开会话会把用户消息（含图片）、回答、工具过程和用量重新变为可见记录。发送图片时，真实图片数据也随请求交给服务端校验并保存。SessionStore.list/load · _internal · _transcript
    扩展 → 工具注册表内置工具和 MCP 公开的工具进入同一声明表；Skill 通过 read_skill 读取正文。它们不是另一条聊天入口。tools.build → tool_specs → mcp_tool_specs
    工作目录与配置 → 本轮装配工作目录决定路径根、Git/说明文件背景和项目 Skill；分组的 MCP 服务启动时使用工作目录。权限模式与规则决定工具是否需要人工确认。workspace.inspect · default_policy · _start_mcp

    已验证现状、限制与未验证事项

    “已验证”只覆盖这里写出的验证范围

    本轮可复核的现状

    • 用户在图片读取完成后发送，请求携带附件数据；发送之前的附件快照不会在新建会话等待中被替换。
    • 会话记录中的用户图片由 items[*].images = [{mime,data}] 返回，网页按原消息展示；仅图片消息也保留正文之外的内容。
    • 工具步骤显示调用参数，结果事件携带参数时以结果为准，未携带时沿用对应调用参数。
    • 后台任务按会话持有；服务退出时关闭任务。停止与人工等待都在当前运行中处理。
    • 三类协议解析、工具声明、权限和会话读写的既有自动化测试可供追溯。

    明确尚未实现的长期方向

    • 持续在用户输入之外自主活动、反思和形成新意图。愿景
    • 由经历持续更新、影响后续行为的长期记忆与自我理解。愿景
    • 人格在长期使用中形成稳定而可变化的状态；当前会话记录不是这样的状态系统。愿景
    • 跨会话共享的子代理上下文、并行编排或由继承父上下文产生的派生运行。未实现

    真实使用边界

    • 没有连接当前提供商的真实模型，未验收真实账号、配额、计费、模型能力声明或供应商兼容差异。
    • 图片能力需在模型中声明；文件写入、命令运行和 MCP 进程的权限仍取决于本机环境与配置，应用层授权不是操作系统沙箱。
    • 摘要与停止是运行时策略；重载后的历史、压缩后的模型输入及已开始的外部操作不是同一件事，不能把“已停止”理解为所有外部动作已回滚。
    • 全新本地数据目录在填写模型 Base URL 前，状态接口会因无效默认配置报错；要使用界面，需先准备有效提供商设置。这是当前启动边界。
